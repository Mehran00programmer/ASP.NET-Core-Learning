01

ساخت اولین اپلیکیشن ASP.NET Core

قبل از نوشتن کد، باید یک پروژه جدید بسازیم. در Visual Studio گزینه Create a new project را انتخاب کنید، سپس از فهرست قالب‌ها ASP.NET Core Web App (Model-View-Controller) را پیدا کنید[reference:6]. به این قالب دقت کنید؛ چون قالب Razor Pages هم شبیه است اما ساختار متفاوتی دارد.

در پنجره بعدی نام پروژه را وارد کنید (مثلاً MvcMovie) و محل ذخیره را انتخاب کنید[reference:7]. در آخرین مرحله، نسخه .NET را انتخاب کنید. پیشنهاد می‌کنم جدیدترین نسخه LTS (پشتیبانی بلندمدت) را انتخاب کنید تا تا مدت‌ها پشتیبانی شود. بعد از زدن دکمه Create، پروژه ساخته می‌شود و آماده اجراست.

برای اجرای پروژه کافی است کلید F5 را بزنید یا روی دکمه سبز Run کلیک کنید. مرورگر باز می‌شود و صفحه پیش‌فرض ASP.NET Core را می‌بینید. اگر این صفحه را دیدید، یعنی همه‌چیز درست کار می‌کند و آماده ادامه مسیر هستیم.

نکته

اگر با Visual Studio Code کار می‌کنید، می‌توانید از دستور dotnet new mvc -n MvcMovie در ترمینال استفاده کنید. سپس با dotnet run پروژه را اجرا کنید.

02

ساختار پروژه MVC

وقتی پروژه ساخته می‌شود، مجموعه‌ای از پوشه‌ها و فایل‌ها می‌بینید که هر کدام جای مشخصی دارند. این ساختار تصادفی نیست؛ دقیقاً بر اساس الگوی MVC چیده شده است[reference:8]. سه پوشه اصلی Controllers، Models و Views هستند که به ترتیب کنترل‌کننده‌ها، مدل‌ها و نمایش‌ها را در خود نگه می‌دارند[reference:9].

  • MvcMovie/
    • Controllers/ کنترل‌کننده‌ها
    • Models/ مدل‌ها
    • Views/ نمایش‌ها
      • Home/ Viewهای HomeController
      • Shared/ Viewهای مشترک
    • wwwroot/ فایل‌های استاتیک
    • Program.cs نقطه شروع برنامه
    • appsettings.json تنظیمات

پوشه Controllers تمام کلاس‌های کنترل‌کننده را نگه می‌دارد. یک قانون نام‌گذاری مهم وجود دارد: نام هر کنترل‌کننده باید به Controller ختم شود (مثلاً HomeController)[reference:10]. پوشه Models کلاس‌های داده را در خود دارد. پوشه Views فایل‌های نمایشی Razor (با پسوند .cshtml) را نگه می‌دارد و معمولاً برای هر کنترل‌کننده یک زیرپوشه هم‌نام دارد [reference:11]. پوشه wwwroot محل فایل‌های استاتیک مثل CSS، JavaScript و تصاویر است[reference:12]. فایل Program.cs هم نقطه شروع برنامه و محل پیکربندی سرویس‌ها و میان‌افزارهاست.

03

ساخت اولین Controller و View

حالا یک کنترل‌کننده جدید به نام HelloWorldController می‌سازیم. روی پوشه Controllers راست‌کلیک کنید، گزینه Add → Controller را انتخاب کنید و قالب MVC Controller - Empty را بزنید. نام آن را HelloWorldController بگذارید.

داخل کلاس، یک متد به نام Index اضافه کنید که یک رشته برمی‌گرداند:

C# — HelloWorldController.cs 
public IActionResult Index()
{
    return Content("سلام از HelloWorldController!");
}

پروژه را اجرا کنید و به آدرس /HelloWorld بروید. متن «سلام از HelloWorldController!» را می‌بینید. اما برگرداندن رشته خام زیاد جالب نیست؛ بهتر است یک صفحه واقعی HTML داشته باشیم. برای این کار باید View بسازیم.

متد Index را طوری تغییر دهید که به‌جای Content از View() استفاده کند:

C# — HelloWorldController.cs 
public IActionResult Index()
{
    return View();
}

حالا روی پوشه Views راست‌کلیک کنید، پوشه‌ای به نام HelloWorld بسازید (هم‌نام کنترل‌کننده) و داخل آن یک Razor View به نام Index.cshtml اضافه کنید[reference:13]. محتوای آن را به این شکل بنویسید:

HTML — Views/HelloWorld/Index.cshtml 
<h2>صفحه Index از HelloWorld</h2>
<p>این اولین View ما در ASP.NET Core است.</p>

دوباره پروژه را اجرا کنید و به /HelloWorld بروید. حالا صفحه HTML واقعی را می‌بینید. نکته مهم این است که نام فایل View باید با نام متد اکشن یکی باشد (Index.cshtml برای متد Index) و پوشه آن هم باید هم‌نام کنترل‌کننده باشد. این همان قانون «قرارداد بر پیکربندی» است که ASP.NET Core را ساده نگه می‌دارد.

04

اتریبیوت‌های Controller

اتریبیوت‌ها برچسب‌هایی هستند که بالای کلاس یا متد می‌نویسید و به فریم‌ورک می‌گویند چطور رفتار کند. مهم‌ترین اتریبیوت‌های Controller در ASP.NET Core این‌ها هستند: [Route]، [HttpGet]، [HttpPost]، [HttpPut]، [HttpDelete]، و [ApiController][reference:14][reference:15].

اتریبیوت [Route] مسیر URL را تعیین می‌کند. می‌توانید آن را بالای کلاس بگذارید تا پیشوند همه اکشن‌ها را تعیین کند، یا بالای یک اکشن خاص. اتریبیوت‌های [HttpGet] و مشابه‌هایش مشخص می‌کنند که اکشن فقط به درخواست‌های HTTP با آن متد پاسخ دهد[reference:16]. این‌ها همان چیزی هستند که در قسمت اول درباره HTTP Method یاد گرفتیم، حالا در کد پیاده می‌شوند.

چرا اتریبیوت مهم است؟

بدون اتریبیوت، یک اکشن به همه نوع درخواست‌ها پاسخ می‌دهد. با گذاشتن [HttpGet] مطمئن می‌شوید این اکشن فقط برای نمایش صفحه است، نه برای ارسال فرم. این کار امنیت و خوانایی کد را بالا می‌برد.

05

Action Selector و Action Verb

وقتی درخواستی به یک کنترل‌کننده می‌رسد، ASP.NET Core باید تصمیم بگیرد کدام متد (اکشن) را اجرا کند. به این فرآیند Action Selection می‌گویند. اکشن‌ها بر اساس نام، اتریبیوت HTTP و پارامترها انتخاب می‌شوند [reference:17].

Action Verb یا فعل اکشن همان HTTP Method است که اکشن به آن محدود شده. مثلاً اگر متدی اتریبیوت [HttpPost] داشته باشد، فقط با درخواست POST اجرا می‌شود. اگر متدی هیچ اتریبیوتی نداشته باشد، به‌طور پیش‌فرض با GET مطابقت داده می‌شود.

یک نکته مهم: اگر دو اکشن با یک نام و یک مسیر داشته باشید اما یکی [HttpGet] و دیگری [HttpPost] باشد، تداخلی پیش نمی‌آید چون Action Selector بر اساس HTTP Method آن‌ها را از هم تفکیک می‌کند [reference:18].

06

ساخت اولین Model

تا اینجا فقط متن نمایش دادیم. اما برنامه واقعی با داده کار می‌کند. Model کلاسی است که ساختار داده را تعریف می‌کند. مثلاً یک مدل ساده برای «فیلم»:

C# — Models/Movie.cs 
public class Movie
{
    public int Id { get; set; }
    public string Title { get; set; } = "";
    public string Genre { get; set; } = "";
    public decimal Price { get; set; }
}

این کلاس هیچ منطقی ندارد؛ فقط ظرفی برای نگه‌داری داده است. در قسمت‌های بعدی یاد می‌گیریم چطور این مدل را به دیتابیس وصل کنیم. فعلاً همین اندازه کافی است تا داده را به View بفرستیم.

07

ViewBag و ViewData

Controller باید داده را به View برساند. دو راه ساده برای این کار وجود دارد: ViewData و ViewBag. هر دو فقط در طول یک درخواست زنده‌اند و بعد از رندر شدن View از بین می‌روند[reference:19].

ViewData

ViewData یک دیکشنری از جفت‌های کلید-مقدار است. در Controller می‌نویسید:

C# — Controller 
ViewData["Message"] = "سلام از ViewData";
ViewData["Count"] = 5;

و در View:

HTML — View 
<p>@ViewData["Message"]</p>
<p>تعداد: @ViewData["Count"]</p>

چون ViewData از نوع object است، برای استفاده از مقادیر غیر رشته‌ای باید تبدیل نوع انجام دهید.

ViewBag

ViewBag در واقع همان ViewData است اما با یک پوسته dynamic. این یعنی می‌توانید به‌جای ViewData["Message"] بنویسید ViewBag.Message. کد تمیزتر به نظر می‌رسد، اما چون dynamic است، خطاهای نام‌گذاری در زمان کامپایل گرفته نمی‌شوند و ممکن است در زمان اجرا به مشکل بخورید[reference:20].

C# — Controller 
ViewBag.Message = "سلام از ViewBag";
ViewBag.Count = 5;
HTML — View 
<p>@ViewBag.Message</p>
<p>تعداد: @ViewBag.Count</p>
توصیه

برای پروژه‌های جدی، به‌جای ViewBag و ViewData از یک ViewModel قوی‌تایپ (کلاس مدل مخصوص View) استفاده کنید. این کار خطاها را در زمان کامپایل نشان می‌دهد.

08

TempData

فرض کنید کاربر فرمی را پر می‌کند و بعد از ثبت موفق، به صفحه دیگری redirect می‌شود. ViewBag و ViewData در redirect از بین می‌روند. اینجاست که TempData وارد می‌شود. TempData داده را برای یک درخواست بعدی نگه می‌دارد[reference:21][reference:22].

C# — Controller 
TempData["Success"] = "عملیات با موفقیت انجام شد.";
return RedirectToAction("Index");
HTML — View 
@if (TempData["Success"] != null)
{
    <div class="alert">@TempData["Success"]</div>
}

یک رفتار مهم: به‌طور پیش‌فرض، TempData وقتی خوانده شود پاک می‌شود[reference:23]. اگر می‌خواهید بعد از خواندن هم باقی بماند، از TempData.Keep() استفاده کنید.

09

Query String

Query String بخشی از URL است که بعد از علامت سؤال ? می‌آید و شامل جفت‌های کلید-مقدار است. مثلاً در آدرس /HelloWorld/Welcome?name=Mehran&numtimes=3، دو پارامتر name و numtimes در Query String قرار دارند[reference:24].

ASP.NET Core به‌طور خودکار این پارامترها را با پارامترهای متد اکشن تطبیق می‌دهد. اگر متد شما این‌طور باشد:

C# — Controller 
public IActionResult Welcome(string name, int numtimes = 1)
{
    ViewData["Name"] = name;
    ViewData["NumTimes"] = numtimes;
    return View();
}

با آدرس /HelloWorld/Welcome?name=Mehran&numtimes=3، مقدار name برابر «Mehran» و numtimes برابر ۳ خواهد بود. اگر پارامتری در URL نباشد، مقدار پیش‌فرض (در اینجا ۱) استفاده می‌شود.

نکته امنیتی

هرگز داده حساس (مثل رمز عبور یا توکن) را در Query String نفرستید، چون در تاریخچه مرورگر، لاگ سرور و هدر Referer ذخیره می‌شود.

10

Model Binding

Model Binding مکانیزمی است که داده‌های یک درخواست HTTP را می‌گیرد و به پارامترهای متد اکشن تبدیل می‌کند[reference:25]. بدون Model Binding باید خودتان دستی از Request.Query یا Request.Form مقدار می‌خواندید. اما ASP.NET Core این کار را خودکار انجام می‌دهد.

منابعی که Model Binding از آن‌ها داده می‌خواند عبارت‌اند از: فرم‌ها، داده مسیر (Route Data)، Query String، و بدنه درخواست (برای JSON و XML)[reference:26]. ترتیب اولویت پیش‌فرض به این شکل است که فرم‌ها اول بررسی می‌شوند، سپس داده مسیر، سپس Query String و در آخر بدنه.

یک نکته مهم: Model Binding برای انواع ساده (مثل int، string، DateTime) از داده مسیر و Query String استفاده می‌کند، اما برای انواع پیچیده (کلاس‌ها) باید منبع داده را با اتریبیوت مشخص کنید[reference:27].

11

اتریبیوت‌های Model Binding

وقتی نمی‌خواهید Model Binding حدس بزند داده را از کجا بخواند، از این اتریبیوت‌ها استفاده می‌کنید. مهم‌ترین‌ها [FromQuery]، [FromRoute]، [FromForm]، [FromBody] و [FromHeader] هستند[reference:28][reference:29].

اتریبیوتمنبع داده
[FromQuery]Query String در URL
[FromRoute]داده مسیر (مثل /products/5)
[FromForm]داده فرم HTML
[FromBody]بدنه درخواست (JSON / XML)
[FromHeader]هدرهای HTTP

مثال استفاده از [FromQuery]:

C# — Controller 
public IActionResult Search([FromQuery] string term)
{
    return Content($"جستجو برای: {term}");
}

استفاده از [FromBody] برای دریافت JSON:

C# — Controller 
[HttpPost]
public IActionResult Create([FromBody] Movie movie)
{
    return Ok(movie);
}
بهترین تمرین

همیشه از اتریبیوت‌های صریح استفاده کنید. این کار کد را خودمستند می‌کند و جلوی حدس‌های نادرست Model Binding را می‌گیرد.

12

دیباگ و Breakpoint

وقتی کد درست کار نمی‌کند، اولین ابزار شما Breakpoint است. روی حاشیه سمت چپ خط مورد نظر در Visual Studio کلیک کنید تا یک نقطه قرمز ظاهر شود. سپس F5 را بزنید تا برنامه در حالت دیباگ اجرا شود. وقتی اجرا به آن خط برسد، متوقف می‌شود و می‌توانید مقدار متغیرها را ببینید [reference:31][reference:32].

چند نکته کاربردی: با F10 خط به خط جلو می‌روید (Step Over)، با F11 وارد متد می‌شوید (Step Into)، و با F5 ادامه می‌دهید تا به Breakpoint بعدی برسید. پنجره‌های Locals، Watch و Autos مقادیر متغیرها را نشان می‌دهند.

اگر Breakpoint فعال نمی‌شود، بررسی کنید که در حالت Debug اجرا می‌کنید (نه Release) و گزینه Just My Code در تنظیمات دیباگ درست تنظیم شده است[reference:33]. برای اکشن‌های ASP.NET Core، Breakpoint را داخل متد اکشن یا هر جای زنجیره درخواست بگذارید و از مرورگر یا یک کلاینت HTTP برای تحریک درخواست استفاده کنید[reference:34].
