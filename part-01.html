01

نیاز به زبان سمت سرور

پیش از این، تمرکز ما روی برنامه‌نویسی سمت کلاینت بود؛ یعنی کدی که در مرورگر کاربر اجرا می‌شود. با سه تکنولوژی اصلی HTML، CSS و JavaScript می‌توانیم صفحاتی زیبا، واکنش‌گرا و حتی تعاملی بسازیم. اما این سه، یک محدودیت بنیادین دارند: آن‌ها نمی‌توانند در سمت سرور کد اجرا کنند.

در وب دقیقاً چه اتفاقی می‌افتد؟

زمانی که آدرس یک وب‌سایت را در نوار آدرس مرورگر وارد می‌کنید، مرورگر یک درخواست (Request) به سمت سرور ارسال می‌کند. سرور این درخواست را دریافت، پردازش و پاسخ مناسب را برای مرورگر می‌فرستد. پاسخ نهایی چیزی نیست جز فایل‌های HTML، CSS و JavaScript که مرورگر آن‌ها را تفسیر و به صفحه‌ای قابل مشاهده تبدیل می‌کند.

نکته کلیدی

تا این مرحله، ما فقط می‌توانستیم داده‌ها را دریافت کنیم. اما اگر کاربر بخواهد داده‌ای را به سایت بفرستد و آن را در سرور ذخیره کند — مانند ثبت‌نام، ثبت سفارش، ارسال نظر، ویرایش پروفایل یا پرداخت — دیگر HTML و CSS به‌تنهایی کارساز نیستند.

توانمندی‌های یک زبان سمت سرور

با یادگیری یک زبان برنامه‌نویسی سمت سرور، درهای تازه‌ای به روی ما باز می‌شود. مهم‌ترین توانایی‌هایی که به دست می‌آوریم عبارتند از:

  • دریافت داده از کاربر: خواندن اطلاعات فرم‌ها، پارامترهای آدرس و کوکی‌ها.
  • ذخیره‌سازی داده: نگه‌داشتن اطلاعات در دیتابیس، فایل یا حافظه سرور.
  • ویرایش و حذف داده: به‌روزرسانی و حذف رکوردهای موجود در دیتابیس.
  • بازیابی و ارسال داده: خواندن اطلاعات از دیتابیس و نمایش آن‌ها به کاربر.
  • اعتبارسنجی و امنیت: بررسی صحت داده‌ها، مدیریت نشست‌ها و احراز هویت.
نکته امنیتی

کدهای سمت سرور هرگز در مرورگر کاربر دیده نمی‌شوند. آن‌ها فقط در سرور اجرا می‌شوند و صرفاً خروجی نهایی — که معمولاً HTML است — به مرورگر ارسال می‌شود. این ویژگی باعث می‌شود منطق برنامه، الگوریتم‌ها و اطلاعات حساس، از دید کاربر پنهان بمانند.

تکنولوژی‌های مورد استفاده

زبان‌ها و تکنولوژی‌های متعددی برای برنامه‌نویسی سمت سرور وجود دارد. در این جزوه، تمرکز ما روی مجموعه‌ای از محصولات مایکروسافت است:

مورد انتخاب توضیح
زبان برنامه‌نویسی C# زبانی مدرن، شی‌گرا و قدرتمند از مایکروسافت
تکنولوژی ASP.NET فریم‌ورک مایکروسافت برای ساخت اپلیکیشن‌های وب
محیط توسعه Visual Studio IDE رسمی مایکروسافت برای توسعه .NET
الگوی معماری MVC الگوی جداسازی منطق، نمایش و کنترل
توجه

ASP.NET یک زبان برنامه‌نویسی نیست؛ بلکه یک تکنولوژی یا فریم‌ورک است که توسط مایکروسافت ارائه شده. ما با زبان C# کد می‌نویسیم و از ASP.NET برای تبدیل آن کد به یک وب‌سایت قابل اجرا استفاده می‌کنیم.

02

الگوی طراحی MVC

MVC مخفف سه کلمه Model (مدل)، View (نمایش) و Controller (کنترل‌کننده) است. این یک الگوی طراحی معماری است که یک برنامه وب را به سه بخش مستقل تقسیم می‌کند. هدف اصلی این تقسیم‌بندی، مدیریت پیچیدگی و جداسازی دغدغه‌ها است تا توسعه، نگهداری و تست برنامه ساده‌تر شود.

کاربر درخواست را به Controller می‌فرستد و از او پاسخ می‌گیرد — View و Model هر دو تحت کنترل Controller هستند

سه جزء اصلی MVC

Model — مدل

مدل نماینده داده‌ها و منطق تجاری برنامه است. هر چیزی که مربوط به ساختار داده‌ها، قوانین اعتبارسنجی، محاسبات و تعامل با دیتابیس باشد، در Model قرار می‌گیرد. Model با زبان C# نوشته می‌شود و معمولاً کلاس‌هایی هستند که ویژگی‌ها (Properties) و متدهای مربوط به داده را تعریف می‌کنند.

برای مثال، در یک فروشگاه اینترنتی، کلاس Product که شامل Id، Name، Price و Stock است، یک Model محسوب می‌شود.

View — نمایش

View همان چیزی است که کاربر نهایی می‌بیند. تمام صفحاتی که با HTML، CSS و JavaScript ساخته می‌شوند در بخش View قرار می‌گیرند. View مسئول نمایش داده‌ها به کاربر است و نباید منطق تجاری پیچیده‌ای در آن قرار بگیرد. در ASP.NET MVC، View‌ها معمولاً با زبان نشانه‌گذاری Razor (پسوند .cshtml) نوشته می‌شوند.

Controller — کنترل‌کننده

Controller قلب تپنده برنامه است و وظیفه برقراری ارتباط بین Model و View را بر عهده دارد. وقتی کاربر درخواستی می‌فرستد، Controller آن را دریافت می‌کند، در صورت نیاز به Model مراجعه می‌کند و سپس داده‌ها را به View می‌فرستد تا نمایش داده شوند. Controller با زبان C# نوشته می‌شود.

قانون طلایی MVC

Model و Controller با C# نوشته می‌شوند و View با HTML/CSS/JavaScript. Controller هرگز مستقیماً داده‌ها را نمایش نمی‌دهد و View هرگز مستقیماً به دیتابیس دسترسی ندارد. هر جزء فقط وظیفه خودش را انجام می‌دهد.

03

چرخه پردازش درخواست

برای درک دقیق MVC، باید بدانیم وقتی کاربر یک آدرس را در مرورگر وارد می‌کند، در سرور واقعاً چه اتفاقی می‌افتد. نکته مهم این است که View هیچ‌وقت درخواست نمی‌فرستد؛ View یک قالب روی سرور است که یک بار رندر می‌شود و به HTML تبدیل می‌شود. آنچه کاربر با آن تعامل می‌کند، HTML نهایی است که مرورگر نمایش می‌دهد. درخواست بعدی هم از طرف مرورگر به سرور ارسال می‌شود، نه از طرف View.

چرخه کامل پردازش درخواست — از ورود آدرس تا نمایش نتیجه به کاربر

شرح گام‌ها

  1. کاربر آدرس را در مرورگر وارد می‌کند کاربر یک URL را در نوار آدرس مرورگر تایپ می‌کند، روی لینکی کلیک می‌کند یا فرمی را ارسال می‌کند.
  2. مرورگر درخواست HTTP را به سرور ارسال می‌کند مرورگر بر اساس آدرس، یک درخواست HTTP می‌سازد و آن را به سرور می‌فرستد.
  3. سیستم Routing درخواست را به Controller هدایت می‌کند در ASP.NET MVC، سیستم مسیریابی الگوی آدرس را بررسی کرده و آن را به Controller و Action مناسب هدایت می‌کند.
  4. Controller در صورت نیاز با Model ارتباط می‌گیرد اگر اکشن به داده نیاز داشته باشد، Controller از Model درخواست می‌کند. Model داده‌ها را از دیتابیس خوانده و به Controller برمی‌گرداند.
  5. Controller داده‌ها را به View می‌فرستد تا رندر شود Controller داده‌ها را به یک View می‌فرستد. View روی سرور اجرا شده و به HTML نهایی تبدیل می‌شود.
  6. HTML نهایی به مرورگر برگشته و به کاربر نمایش داده می‌شود مرورگر HTML دریافتی را تفسیر و به صفحه‌ای قابل مشاهده برای کاربر تبدیل می‌کند. برای درخواست بعدی، همین چرخه از ابتدا تکرار می‌شود.
نکته فنی

نکته مهمی که گاهی در توضیحات ساده‌سازی‌شده نادیده گرفته می‌شود این است که View هیچ‌وقت درخواست نمی‌فرستد. View یک قالب روی سرور است که صرفاً یک بار رندر می‌شود. آنچه کاربر با آن تعامل دارد، HTML نهایی است که مرورگر نمایش داده. درخواست بعدی هم مستقیم از طرف مرورگر به Controller می‌رود.

نکته مهم

کاربر می‌تواند مستقیماً یک URL را در مرورگر وارد کند و بدون اینکه قبلاً هیچ صفحه‌ای از سایت را دیده باشد، به Controller برود. همچنین در APIها که اصلاً View وجود ندارد، درخواست مستقیم به Controller می‌رود و Controller به‌جای View، داده JSON برمی‌گرداند. این نشان می‌دهد Controller کاملاً مستقل از View عمل می‌کند.

04

ساختار پروژه ASP.NET MVC

وقتی یک پروژه ASP.NET MVC جدید در Visual Studio ایجاد می‌کنید، به‌صورت پیش‌فرض چند پوشه و فایل برای شما ساخته می‌شود. آشنایی با این ساختار برای شروع کار ضروری است، چون MVC بر پایه قرارداد (Convention) کار می‌کند و محل قرارگیری فایل‌ها اهمیت زیادی دارد.

  • Controllers
    • HomeController.cs کنترل‌کننده اصلی
  • Models
    • کلاس‌های مدل اینجا قرار می‌گیرند
  • Views
    • Home
      • Index.cshtml صفحه اصلی
      • About.cshtml درباره ما
    • Shared
      • _Layout.cshtml قالب اصلی
      • _ViewStart.cshtml تنظیمات اولیه
  • App_Data فایل‌های داده
  • Content CSS و تصاویر
  • Scripts فایل‌های JavaScript
  • Web.config تنظیمات برنامه
  • Global.asax رویدادهای برنامه

توضیح پوشه‌های مهم

پوشه / فایلکاربرد
Controllers/ محل قرارگیری کلاس‌های Controller. نام کلاس‌ها باید با پسوند Controller تمام شود.
Models/ کلاس‌های مدل که ساختار داده و منطق تجاری را تعریف می‌کنند.
Views/ فایل‌های نمایشی (Razor View) که خروجی HTML تولید می‌کنند.
App_Data/ محل ذخیره‌سازی فیزیکی داده‌ها (فایل‌های دیتابیس، XML و...).
Content/ فایل‌های ایستا مانند CSS، تصاویر و فونت‌ها.
Scripts/ فایل‌های JavaScript پروژه.
قرارداد پیش‌فرض (Convention over Configuration)

ASP.NET MVC بر پایه «قرارداد» کار می‌کند. اگر Controller شما HomeController نام داشته باشد، به‌صورت خودکار به دنبال View‌های مربوطه در پوشه Views/Home/ می‌گردد. این یعنی نیازی به تنظیم دستی مسیرها ندارید و می‌توانید روی منطق برنامه تمرکز کنید.

05

اولین پروژه عملی

پس از آشنایی با مفاهیم نظری، حالا مراحل ساخت یک پروژه ساده ASP.NET MVC را مرور می‌کنیم.

پیش‌نیازها

  • Visual Studio نسخه ۲۰۱۰ یا بالاتر — یا Visual Web Developer Express.
  • .NET Framework نصب‌شده روی سیستم‌عامل.
  • آشنایی مقدماتی با زبان C# و مفاهیم شی‌گرایی.

مراحل ساخت پروژه

  1. اجرای Visual Studio برنامه را اجرا کنید و از منوی File گزینه New Project را انتخاب کنید.
  2. انتخاب زبان برنامه‌نویسی در پنجره باز شده، از سمت چپ زبان Visual C# را انتخاب کنید.
  3. انتخاب قالب پروژه از قالب‌های موجود، ASP.NET MVC Web Application را انتخاب کنید.
  4. نام‌گذاری پروژه نام پروژه را وارد کنید (مثلاً Movies) و روی OK کلیک کنید.
  5. ساخت خودکار پروژه پروژه به‌صورت خودکار با یک قالب پیش‌فرض ساخته می‌شود که شامل یک صفحه Hello World است.

اجرای پروژه

برای اجرای پروژه کافی است روی دکمه Play (فلش سبز) در نوار ابزار کلیک کنید یا کلید F5 را بزنید. مرورگر به‌صورت خودکار باز می‌شود و آدرس localhost را نمایش می‌دهد که به کامپیوتر محلی خودتان اشاره می‌کند.

توجه

در ASP.NET MVC، برخلاف Web Forms، چرخه صفحه (Page Life Cycle) به آن شکل کلاسیک وجود ندارد. درخواست‌ها مستقیماً از طریق روتینگ (Routing) به Controller هدایت می‌شوند و اکشن‌ها پردازش را انجام می‌دهند.

06

مزایای استفاده از MVC

MVC به دلیل جداسازی دغدغه‌ها (Separation of Concerns) مزایای متعددی دارد که آن را به انتخاب مناسبی برای برنامه‌های وب پویا تبدیل می‌کند.

قابلیت نگهداری بالا
هر بخش (Model، View، Controller) یک وظیفه مشخص دارد و تغییر در یکی، بخش‌های دیگر را تحت تأثیر قرار نمی‌دهد.
تست‌پذیری
Model و Controller را می‌توان به‌صورت مستقل از View تست کرد. این کار کیفیت کد را بسیار افزایش می‌دهد.
کار تیمی بهتر
تیم طراحی UI می‌تواند روی View کار کند و تیم بک‌اند روی Model و Controller، بدون تداخل.
مقیاس‌پذیری
پروژه‌های بزرگ را می‌توان به‌راحتی بین اعضای تیم تقسیم کرد و توسعه داد.
مقایسه با Web Forms

در Web Forms، منطق برنامه با ظاهر صفحه کاملاً درهم تنیده بود و همین موضوع نگهداری و تست را دشوار می‌کرد. اما در MVC، این دو کاملاً از هم جدا هستند و همین موضوع باعث می‌شود MVC برای پروژه‌های پویا و مدرن انتخاب بهتری باشد.

07

خلاصه مطالب

در این قسمت با مفاهیم بنیادین برنامه‌نویسی سمت سرور و الگوی معماری MVC آشنا شدیم. جدول زیر خلاصه‌ای از مهم‌ترین نکات مطرح‌شده است.

مفهومخلاصه
سمت سرور زبان‌های سمت سرور امکان ذخیره، ویرایش و بازیابی داده‌ها را می‌دهند. کدهای آن‌ها در مرورگر دیده نمی‌شوند.
ASP.NET یک تکنولوژی مایکروسافتی است (نه یک زبان) که با C# در Visual Studio کار می‌کند.
الگوی MVC برنامه را به سه بخش Model (داده‌ها)، View (نمایش) و Controller (کنترل‌کننده) تقسیم می‌کند.
Controller واسطه بین Model و View است. درخواست‌ها را دریافت و به بخش مناسب هدایت می‌کند.
Model نماینده داده‌ها و منطق تجاری برنامه است. با C# نوشته می‌شود.
View خروجی HTML/CSS/JS است که کاربر می‌بیند.
