آشنایی با .NET و .NET Standard

قبل از اینکه وارد دنیای برنامه‌نویسی وب شویم، باید بدانیم که قرار است با چه ابزاری کار کنیم. در این بخش می‌خواهیم مفهوم .NET را از صفر و به زبان ساده یاد بگیریم. این مفهوم پایه و اساس تمام چیزهایی است که در ادامه این مسیر یادگیری با آن‌ها روبه‌رو خواهید شد.

.NET چیست؟ (به زبان ساده)

تصور کنید می‌خواهید یک خانه بسازید. برای این کار به مصالح مختلفی نیاز دارید: آجر، سیمان، چوب، شیشه و... . همچنین به ابزارهایی نیاز دارید: ماله، بیل، چکش و... . علاوه بر این‌ها، به یک نقشه و نقشه‌کش هم نیاز دارید که بداند چه چیزی را کجا قرار دهد. .NET هم دقیقاً همین نقش را برای برنامه‌نویسان بازی می‌کند.

.NET یک پلتفرم توسعه نرم‌افزار است. یعنی یک محیط کامل که همه ابزارها، کتابخانه‌ها و امکانات لازم برای ساخت برنامه‌های کامپیوتری را در اختیار برنامه‌نویس قرار می‌دهد. این پلتفرم توسط شرکت مایکروسافت ساخته شده و اولین نسخه آن در سال ۲۰۰۲ منتشر شد.

.NET یک پلتفرم توسعه نرم‌افزاری و اپن‌سورس است که شامل چندین فریم‌ورک مختلف نظیر .NET Framework، .NET Core و .NET 8 می‌شود و امکان اجرا بر روی سیستم‌عامل‌های مختلف از جمله Windows، Linux و macOS را دارد.

.NET به یک فریم‌ورک کلان نرم‌افزاری اشاره می‌کند که امکان توسعه برنامه‌های متنوع را در محیط‌های مختلف فراهم می‌کند. این پلتفرم از زبان‌های برنامه‌نویسی متنوعی مانند C#، VB.NET و F# پشتیبانی می‌کند.

نکته بسیار مهم

خیلی از افراد تازه‌کار اشتباه می‌کنند و فکر می‌کنند .NET یک زبان برنامه‌نویسی است. این اشتباه است! .NET یک پلتفرم یا محیط اجرا است. زبان برنامه‌نویسی چیزی است که با آن کد می‌نویسید (مثل C#)، در حالی که پلتفرم چیزی است که کد شما را اجرا می‌کند.

مثال ساده: C# مثل زبان فارسی است که با آن حرف می‌زنید، و .NET مثل یک کشور است که در آن زندگی می‌کنید و قوانین و امکانات آن کشور به شما اجازه می‌دهد کارهایتان را انجام دهید.

اجزای اصلی .NET

پلتفرم .NET از چند بخش اصلی تشکیل شده است. درک این بخش‌ها به شما کمک می‌کند بفهمید وقتی کدی می‌نویسید، واقعاً در پشت صحنه چه اتفاقی می‌افتد.

۱. زبان‌های برنامه‌نویسی

اولین بخش، زبان‌هایی هستند که با آن‌ها کد می‌نویسید. معروف‌ترین زبان .NET، زبان C# است. این زبان توسط آقای Anders Hejlsberg طراحی شده و ترکیبی از قدرت زبان C++ و سادگی زبان Java است.

زبان‌های دیگری هم روی .NET وجود دارند:

  • C# (سی‌شارپ): محبوب‌ترین زبان، پرکاربردترین در وب و دسکتاپ
  • F# (اف‌شارپ): یک زبان تابعی (Functional) که برای محاسبات علمی و ریاضی مناسب است
  • VB.NET: نسخه مدرن زبان Visual Basic که ساده‌تر از C# است

۲. کتابخانه کلاس پایه (BCL)

BCL مخفف Base Class Library است و به معنی «کتابخانه کلاس پایه» می‌باشد. این بخش، یک مجموعه بسیار بزرگ از کلاس‌ها و توابع آماده است که کارهای رایج برنامه‌نویسی را برای شما ساده می‌کند.

فرض کنید می‌خواهید یک فایل متنی بسازید و در آن چیزی بنویسید. به‌جای اینکه از صفر کد بنویسید که چطور با دیسک سخت کار کنید، چطور بایت‌ها را ذخیره کنید و...، فقط از کلاس آماده File استفاده می‌کنید. همین موضوع برای کار با متن (کلاس String)، تاریخ و ساعت (کلاس DateTime)، ریاضیات (کلاس Math) و صدها مورد دیگر وجود دارد.

۳. محیط اجرای مشترک زبان (CLR)

CLR مخفف Common Language Runtime است و به معنی «محیط اجرای مشترک زبان» می‌باشد. این بخش، موتور اصلی پلتفرم .NET است که کد شما را اجرا می‌کند.

برای درک CLR، این‌طور فکر کنید: وقتی شما با زبان C# کد می‌نویسید، کامپیوتر این کد را مستقیماً نمی‌فهمد. ابتدا کد شما به یک زبان میانی به نام IL (Intermediate Language) ترجمه می‌شود. سپس CLR این زبان میانی را در زمان اجرا به کد ماشین (کدی که پردازنده کامپیوتر می‌فهمد) تبدیل می‌کند.

CLR وظایف مهم دیگری هم دارد:

  • مدیریت حافظه (اختصاص و آزادسازی خودکار حافظه)
  • مدیریت خطاها و استثناها
  • بررسی امنیت کد
  • مدیریت همزمانی و چندریسمانی (Multithreading)
مقایسه ساده

CLR برای .NET مثل موتور برای خودرو است. خودرو بدون موتور حرکت نمی‌کند، کد .NET هم بدون CLR اجرا نمی‌شود.

۴. زیرساخت زبان مشترک (CLI)

CLI مخفف Common Language Infrastructure است و به معنی «زیرساخت زبان مشترک» می‌باشد. CLI یک مشخصات فنی است که تعریف می‌کند کد .NET چطور باید اجرا شود و انواع داده‌ها چه ویژگی‌هایی دارند.

مایکروسافت این مشخصات را به سازمان استانداردسازی ECMA ارائه کرد تا شرکت‌های دیگر هم بتوانند پیاده‌سازی خودشان را از .NET بسازند. به لطف این کار، الان پیاده‌سازی‌های دیگری مثل Mono هم وجود دارند.

۵. سیستم نوع مشترک (CTS)

CTS مخفف Common Type System است و به معنی «سیستم نوع مشترک» می‌باشد. این بخش مشخص می‌کند که انواع داده‌ها (مثل int، string، bool و...) در پلتفرم .NET چه ویژگی‌هایی دارند.

به لطف CTS، می‌توانید یک کلاس در زبان C# بنویسید و همان کلاس را در زبان VB.NET استفاده کنید. این ویژگی باعث می‌شود زبان‌های مختلف .NET بتوانند با هم کار کنند.

تاریخچه .NET

مایکروسافت در اواخر دهه ۱۹۹۰ پروژه‌ای به نام Next Generation Windows Services (به‌اختصار NGWS) را آغاز کرد. هدف این پروژه، ساخت پلتفرمی جدید برای توسعه نرم‌افزار بود که جایگزین تکنولوژی‌های قدیمی مثل COM و ActiveX شود.

در فوریه ۲۰۰۲، اولین نسخه .NET Framework 1.0 منتشر شد. از آن زمان تاکنون نسخه‌های متعددی عرضه شده‌اند:

.NET Standard چیست؟

حالا که فهمیدیم .NET چیست و چند نسخه مختلف دارد، به یک سؤال مهم می‌رسیم: اگر یک برنامه‌نویس کتابخانه‌ای بنویسد که فقط روی .NET Framework کار کند، آیا می‌تواند همان کتابخانه را روی .NET Core هم استفاده کند؟

پاسخ این سؤال قبلاً «نه» بود و این یک مشکل جدی محسوب می‌شد. مایکروسافت برای حل این مشکل، مفهوم .NET Standard را معرفی کرد.

.NET Standard یک استاندارد تعریف‌شده توسط مایکروسافت است که به توسعه‌دهندگان امکان ایجاد کدهای قابل استفاده در انواع فریم‌ورک‌های .NET را می‌دهد. هدف اصلی این استاندارد، ایجاد یک بخش مشترک برای توسعه برنامه‌ها روی انواع فریم‌ورک‌های مختلف .NET است.

به زبان ساده‌تر، .NET Standard یک قرارداد مشترک است که می‌گوید هر پیاده‌سازی از .NET باید حتماً این APIها را داشته باشد. وقتی شما کتابخانه‌ای را بر اساس .NET Standard 2.0 می‌سازید، این کتابخانه روی همه پیاده‌سازی‌هایی که .NET Standard 2.0 را پشتیبانی می‌کنند (شامل .NET Framework 4.6.1 به بالا، .NET Core 2.0 به بالا و Mono 5.4 به بالا) اجرا می‌شود.

تفاوت کلیدی

.NET Standard یک پیاده‌سازی از .NET نیست؛ بلکه مجموعه‌ای از APIها است که کلیه پیاده‌سازی‌های .NET باید آن‌ها را ارائه دهند. در واقع وقتی ما از .NET Standard استفاده می‌کنیم، مشکل اشتراک کد در همه سیستم‌عامل‌ها و پیاده‌سازی‌ها برای .NET برطرف می‌شود.

مزایای استفاده از .NET Standard

  • قابلیت اجرا در چندین فریم‌ورک: کدهای توسعه‌داده‌شده با .NET Standard قابل استفاده در هر فریم‌ورکی است که از آن پشتیبانی کند.
  • قابلیت به‌روزرسانی سریع: به‌روزرسانی‌های کتابخانه‌ها و برنامه‌ها سریع‌تر و ساده‌تر انجام می‌شود.
  • کاهش پیچیدگی‌ها: به‌عنوان یک استاندارد مشترک، پیچیدگی میان فریم‌ورک‌ها را کاهش می‌دهد.
  • پشتیبانی از محیط‌های مختلف: امکان توسعه برنامه‌ها را برای ویندوز، لینوکس و مک فراهم می‌کند.

نسخه‌های .NET Standard

.NET Standard تاکنون چندین نسخه داشته است. هرچه نسخه بالاتر باشد، APIهای بیشتری در دسترس هستند، اما سازگاری با پیاده‌سازی‌های قدیمی‌تر کاهش می‌یابد.

مقایسه .NET Framework و .NET Core

در بخش قبلی فهمیدیم .NET چیست. حالا می‌خواهیم دو پیاده‌سازی مهم آن، یعنی .NET Framework و .NET Core را با هم مقایسه کنیم. این دو، هر دو .NET هستند اما در جزئیات با هم تفاوت‌های اساسی دارند.

.NET Framework چیست؟

.NET Framework یک فریم‌ورک توسعه نرم‌افزار برای ساخت و اجرای برنامه‌های کاربردی در محیط ویندوز است. این فریم‌ورک توسط شرکت مایکروسافت ایجاد شده و ابتدا در سال ۲۰۰۲ عرضه شد.

.NET Framework ابزارها و زیرساخت‌های لازم برای توسعه و اجرای برنامه‌های ویندوزی، وب و سرویس‌های ویندوزی را فراهم می‌کند. این فریم‌ورک به‌طور اصلی بر روی سیستم‌عامل ویندوز اجرا می‌شود و وابستگی به این سیستم‌عامل دارد.

این یعنی اگر شما با .NET Framework برنامه‌ای بنویسید، آن برنامه فقط روی کامپیوترهایی اجرا می‌شود که ویندوز نصب دارند. روی لینوکس یا مک نمی‌توانید آن را اجرا کنید.

.NET Core چیست؟

.NET Core یکی از محصولات شرکت مایکروسافت است که در سال ۲۰۱۶ به بازار عرضه شد. این فریم‌ورک یک ابزار برنامه‌نویسی چندپلتفرمی و منبع‌باز است که روی تمامی پلتفرم‌های رایج در دنیا قابل استفاده است.

.NET Core یک فریم‌ورک سازگار با تمامی سیستم‌عامل‌ها است و قابلیت ساخت برنامه‌های مختلف مناسب اندروید، iOS، ویندوز، لینوکس، وب، فضای ابری، IoT و هوش مصنوعی را دارد. از جمله ویژگی‌های خوب این پلتفرم سرعت و سبکی آن است و فقط برای اجرای قسمت اصلی کد به .NET Core نیاز دارید.

نکته تاریخی

در اواخر سال ۲۰۲۰، .NET Core به .NET 5 تغییر نام داد و در ادامه، تا ویرایش .NET 8 معرفی شد. پس اگر جایی نام .NET 6 یا .NET 8 را دیدید، بدانید که این‌ها همان .NET Core با نام‌های جدید هستند.

چرا .NET Core معرفی شد؟

نسخه قبلی این پلتفرم یعنی .NET Framework، یک ابزار با محدودیت‌های جدی بود. مهم‌ترین ضعف .NET Framework این بود که تنها در سیستم‌عامل ویندوز قابلیت اجرا داشت و روی سایر سیستم‌عامل‌ها قابل استفاده نبود.

بنابراین، اغلب توسعه‌دهندگان به‌علت انحصاری بودن محصولات شرکت مایکروسافت، به‌مرور نسبت به نرم‌افزارهای این شرکت دلسرد شدند. علاوه بر این، امروزه استفاده از برنامه‌هایی که در تمامی دستگاه‌ها قابل اجرا باشند، رایج شده است. یک برنامه قوی باید بتواند تحت وب، روی دسکتاپ و روی تلفن‌های همراه و تبلت‌ها اجرا شود.

به همین علت، نیاز به یک چارچوب واحد احساس می‌شد. در واقع این موضوع، انگیزه اصلی شرکت مایکروسافت برای معرفی ابزار .NET Core بود.

ASP.NET Core چیست؟

حالا که با .NET و نسخه‌های مختلف آن آشنا شدیم، نوبت به ASP.NET Core می‌رسد. این همان چیزی است که در این دوره قرار است با آن وب‌سایت بسازیم.

ASP.NET Core به زبان ساده

تصور کنید .NET یک کارگاه بزرگ است که در آن هر نوع وسیله‌ای می‌توانید بسازید: ماشین، یخچال، تلویزیون و... . ASP.NET Core یکی از دستگاه‌های این کارگاه است که مخصوص ساخت وب‌سایت و سرویس‌های اینترنتی است.

ASP.NET Core یک فریم‌ورک برای توسعه اپلیکیشن‌های مدرن وب و تحت فضای ابری است. این پلتفرم محبوب توسط کمپانی مایکروسافت توسعه داده شده و به‌صورت متن‌باز در گیت‌هاب در دسترس است.

این امر ASP.NET Core را به یک پلتفرم جهانی با قابلیت‌های بسیار و نقص کمتر تبدیل کرده که خود می‌تواند یک عامل مهم در انتخاب آن به‌عنوان یک پلتفرم برای یادگیری توسعه‌دهندگان باشد.

با آن می‌توان برای محیط‌های بک‌اند وب، اینترنت اشیا و اپلیکیشن‌های موبایلی برنامه‌نویسی کرد. این فریم‌ورک طوری طراحی شده است که به اجزای برنامه‌نویسی مانند APIها، کامپایلرها و زبان‌ها اجازه می‌دهد تا به سرعت تکامل پیدا کنند.

ASP.NET Core یک پلتفرم پایه، قدرتمند و در عین حال پشتیبانی‌شده برای توسعه و اجرای برنامه‌ها و اپلیکیشن‌ها ارائه می‌دهد. از جمله مزایای اساسی این فریم‌ورک امکان نصب و راه‌اندازی نسخه‌های مختلف ASP.NET روی یک سرور است. شما می‌توانید با استفاده از آن پروژه‌های دلخواه‌تان را روی یک سرور و با استفاده از نسخه‌های مختلف پیاده‌سازی کنید.

تاریخچه ASP.NET Core

ASP.NET Core اولین بار در سال ۲۰۱۶ منتشر شد و یک طراحی مجدد از نسخه‌های قبلی ASP.NET بود که فقط روی Windows قابل اجرا بود.

ASP.NET Core نسخه اپن‌سورس ASP.NET است که روی MacOS، Linux و Windows اجرا می‌شود.

مزایای استفاده از ASP.NET Core

کاربردهای بسیار زیاد این پلتفرم، باعث محبوبیت آن در میان توسعه‌دهندگان افزایش یافته است. عملاً این زبان یکی از بهترین زبان‌های توسعه نرم‌افزار کراس‌پلتفرم است که مزایای خاص خود را دارا بوده که در ادامه به بررسی آن‌ها می‌پردازیم.

۱. کراس‌پلتفرم (Cross-Platform)

شما با ASP.NET Core می‌توانید تنها با نوشتن یک کد، برنامه موردنظر خود را روی سیستم‌عامل‌های ویندوز، مک و لینوکس اجرا کنید. این یعنی یک بار کد می‌نویسید و روی هر سروری که بخواهید آن را اجرا می‌کنید.

۲. عملکرد بالا

یکی از مهم‌ترین ویژگی‌های هر نرم‌افزار سرعت بالا و کیفیت بالای آن است. ASP.NET Core هر آنچه که لازم دارید تا یک نرم‌افزار بهینه توسعه دهید را در اختیار شما قرار می‌دهد. این پلتفرم محبوب با بهره‌بردن از تکنولوژی IIS و وب‌سرورهای سبک و سریع، توسعه نرم‌افزار را سریع، بهینه و باکیفیت می‌کند.

۳. پشتیبانی از چهارچوب‌های ناهمزمان

ارسال چند درخواست به‌صورت همزمان به سرورها ممکن است سرور را دچار اختلال کند. این موضوع با استفاده از Asynchronous via async/await به‌طور کامل مدیریت می‌شود.

۴. پشتیبانی از MVC و Web API

یکی از ضروری‌ترین امور در پروژه‌ها استفاده از وب‌سرویس‌ها در آن‌ها است؛ چراکه در صورت درست عمل‌نکردن Web API پروژه دچار مشکل می‌شود. اما زمانی که از ASP.NET Core استفاده می‌کنید، درخواست‌ها از HTML به سمت JSON می‌روند سپس در اختیار کاربر قرار می‌گیرند.

مهم

ASP.NET Core یک زبان برنامه‌نویسی نیست؛ بلکه یک فریم‌ورک است. ما با زبان C# کد می‌نویسیم و از ASP.NET Core برای ساخت وب‌سایت‌ها و APIها استفاده می‌کنیم.

الگوی طراحی MVC

حالا که با ASP.NET Core آشنا شدیم، نوبت به الگوی طراحی MVC می‌رسد. این الگو، اسکلت اصلی هر برنامه وب است و درک آن برای ادامه یادگیری بسیار مهم است.

MVC به زبان ساده

MVC یک الگوی طراحی نرم‌افزار یا software design pattern است که مخفف کلمات Model، View و Controller است. این سه بخش نرم‌افزاری همیشه با هم در ارتباط هستند.

برای درک بهتر، یک رستوران را تصور کنید. در یک رستوران سه بخش اصلی وجود دارد:

  • آشپزخانه: جایی که غذا تهیه می‌شود. آشپز دستور پخت را می‌داند و مواد اولیه را از انبار می‌گیرد و غذای نهایی را آماده می‌کند.
  • گارسون: کسی که سفارش مشتری را می‌گیرد، به آشپزخانه می‌برد، و غذای آماده را به مشتری تحویل می‌دهد.
  • سالن رستوران: جایی که مشتری می‌نشیند و غذایش را می‌بیند و می‌خورد.

در MVC هم دقیقاً همین ساختار وجود دارد:

  • Model (مدل): مثل آشپزخانه است. وظیفه دارد داده‌ها را از پایگاه داده دریافت کند، پردازش کند و آماده تحویل دهد.
  • Controller (کنترل‌کننده): مثل گارسون است. درخواست کاربر را دریافت می‌کند، به Model می‌برد، و پاسخ را به View تحویل می‌دهد.
  • View (نمایش): مثل سالن رستوران است. چیزی است که کاربر نهایی می‌بیند و با آن تعامل می‌کند.

سه جزء اصلی MVC

Model — مدل

Model وظیفه ارتباط با پایگاه داده را برعهده دارد. در Model، کلاس‌هایی تعریف می‌شوند که نماینده داده‌های برنامه هستند. مثلاً اگر برنامه شما یک فروشگاه اینترنتی باشد، کلاس‌هایی مثل Product (محصول)، Order (سفارش) و Customer (مشتری) در بخش Model قرار می‌گیرند.

Model همچنین مسئول اعتبارسنجی داده‌ها و منطق تجاری برنامه است. یعنی قوانینی مثل «قیمت محصول نمی‌تواند منفی باشد» یا «نام کاربری باید حداقل ۶ کاراکتر باشد» در این بخش تعریف می‌شوند.

View — نمایش

نقش View، نمایش اطلاعات برای کاربر است. View همان چیزی است که در مرورگر کاربر دیده می‌شود. تمام صفحات وب که با HTML، CSS و JavaScript ساخته می‌شوند، در بخش View قرار می‌گیرند.

در View نباید منطق تجاری پیچیده‌ای وجود داشته باشد. کار View فقط این است که داده‌هایی که از Controller می‌گیرد را به شکل زیبا و قابل فهم به کاربر نشان دهد.

Controller — کنترل‌کننده

Controller رابط بین Model و View است. یعنی اطلاعات را از Model می‌گیرد و جهت نمایش به View ارسال می‌کند.

وقتی کاربر یک آدرس را در مرورگر وارد می‌کند، درخواست او ابتدا به Controller می‌رسد. Controller تصمیم می‌گیرد که چه کاری انجام دهد. آیا نیاز به داده از دیتابیس دارد؟ آیا باید کاربر را به صفحه دیگری هدایت کند؟ آیا باید داده‌ای را ذخیره کند؟

کاربر درخواست را به Controller می‌فرستد و از او پاسخ می‌گیرد — View و Model هر دو تحت کنترل Controller هستند

نحوه کار MVC گام‌به‌گام

ابتدا کاربر درخواستی را توسط مرورگر خود ارسال می‌کند. این درخواست توسط Controller دریافت می‌شود و مورد پردازش قرار می‌گیرد. اگر درخواست به داده نیاز داشته باشد، Controller آن را از Model دریافت می‌کند. و یک View را انتخاب می‌کند و در صورت نیاز مدل/داده که دریافت کرده را به آن ارسال می‌کند. و در آخر View به کاربر در پاسخ درخواست او اطلاعات را نمایش می‌دهد.

مزایای MVC

  • سرعت توسعه: MVC باعث می‌شود هر کد در جای مربوط به خودش باشد و نظمی که ایجاد می‌شود باعث افزایش سرعت توسعه کدها می‌شود.
  • افزایش خوانایی کد: در MVC به علت مرتب‌سازی و تمیز بودن کدها، خوانایی کدها بالاتر می‌رود.
  • آسان‌تر شدن دیباگ کد: در معماری MVC اگر مشکلی در کد ایجاد شود، به دلیل ساختار مناسب و منظم، مشکل کد سریع‌تر رفع می‌شود.
  • تقسیم کاری بین توسعه‌دهندگان: در MVC می‌توان به هر توسعه‌دهنده دسترسی لازم به آن بخش را داد. مثلاً فرانت‌کارها به View دسترسی دارند یا بک‌اند‌کارها به Controllerها.

معایب MVC

  • پیچیدگی MVC زیاد است: اگر برنامه‌نویس حرفه‌ای نباشد ممکن است با ساختار MVC زیاد آشنا نباشد و کار او سخت شود.
  • مناسب نرم‌افزار کوچک نیست: اگر نرم‌افزار شما کوچک باشد و نیازی به توسعه نداشته باشد، MVC باعث افزایش پیچیدگی و کاهش سرعت برنامه خواهد شد.
نتیجه‌گیری

در مجموع ممکن است الگوی MVC در ابتدا کمی پیچیده و مشکل به نظر برسد و ترجیح دهید بدون استفاده از این الگو پروژه‌های خود را پیش ببرید، اما اگر قصد انجام پروژه‌های بزرگ که نیازمند کار تیمی هستند را دارید هرگز از این الگو غافل نشوید. زیرا همان‌طور که در بالا توضیح داده شد این الگو با جداسازی View، Model و Controller امکان کار جداگانه بر روی هر یک از بخش‌ها را فراهم می‌کند.

مقایسه WebForm، MVC و Core

در طول تاریخ، مایکروسافت سه مدل برنامه‌نویسی مختلف برای ساخت وب‌سایت‌ها ارائه کرده است. در این بخش، این سه مدل را به‌طور کامل با هم مقایسه می‌کنیم.

ASP.NET WebForms

ASP.NET WebForms یک فریم‌ورک توسعه وب است که توسط مایکروسافت ارائه شده. این فریم‌ورک به توسعه وب‌سایت‌ها و برنامه‌های وب مبتنی بر سرور در محیط .NET کمک می‌کند. ASP.NET WebForms مبتنی بر مدل ویندوزی (Windows-based) و مدل رویدادی (event-driven) است.

تاریخچه WebForms:

  • در سال ۲۰۰۲ اولین نسخه از ASP.NET Web Forms با .NET Framework 1.0 منتشر شد.
  • در سال ۲۰۰۵ نسخه ASP.NET 2.0 منتشر شد.
  • در سال ۲۰۰۸ نسخه ASP.NET 3.5 با افزونه‌ها و بهبودهای دیگر منتشر شد.
  • در سال ۲۰۱۰ نسخه ASP.NET 4.0 با ویژگی‌های جدیدتری منتشر شد.
  • در سال ۲۰۱۲ نسخه ASP.NET 4.5 با اضافه شدن ASP.NET Web API و SignalR منتشر شد.

مزایا WebForms:

  • سرعت توسعه بالا با استفاده از کنترل‌های کاربری (Server Controls) و مدل برنامه‌نویسی Code-Behind.
  • ویژگی‌های بصری مانند ViewState برای مدیریت وضعیت صفحه.
  • سازگاری با پلتفرم‌ها و وب‌سرورهای مختلف.

معایب WebForms:

  • کد HTML پیچیده و سنگین بودن صفحات.
  • سختی مدیریت وضعیت و Unit Testing.
  • عدم انعطاف‌پذیری وابستگی به وضعیت.

ASP.NET MVC

ASP.NET MVC یک فریم‌ورک توسعه وب است. این فریم‌ورک بر مدل طراحی MVC تکیه دارد که به توسعه وب بر اساس تفکیک وظایف مربوط به مدل (Model)، نمایش (View) و کنترل (Controller) کمک می‌کند.

تاریخچه ASP.NET MVC:

  • در سال ۲۰۰۹ اولین نسخه از ASP.NET MVC با .NET Framework 3.5 منتشر شد.
  • در سال ۲۰۱۰ نسخه ASP.NET MVC 2 منتشر شد.
  • در سال ۲۰۱۱ نسخه ASP.NET MVC 3 با اضافه شدن Razor و برخی ویژگی‌های جدید منتشر شد.
  • در سال ۲۰۱۲ نسخه ASP.NET MVC 4 با افزودن ASP.NET Web API منتشر شد.
  • در سال ۲۰۱۵ نسخه ASP.NET MVC 5 با بهبودها و اضافه شدن امکانات جدید منتشر شد.

مزایا ASP.NET MVC:

  • استفاده از معماری MVC.
  • تمرکز بر روی اصول RESTful و ساختار کلاینت-سرور.
  • قابلیت Unit Testing و امکانات تست‌پذیری بهتر.

معایب ASP.NET MVC:

  • مدیریت فایل‌های JavaScript و CSS مقداری پیچیده است.
  • آشنایی برخی توسعه‌دهندگان با مفاهیم MVC ممکن است زمان‌بر باشد.
  • نیاز به مدیریت بیشتری روی URL و Routing می‌باشد.

ASP.NET Core

ASP.NET Core یک فریم‌ورک توسعه وب و چندپلتفرمی است. این فریم‌ورک به‌عنوان نسخه به‌روز شده و جدیدتر از ASP.NET عرضه شده و برخی از مشکلات و نقاط ضعف پیشین را حل کرده است.

تاریخچه ASP.NET Core:

  • در سال ۲۰۱۶ اولین نسخه از ASP.NET Core 1.0 به‌عنوان یک فریم‌ورک بازسازی‌شده منتشر شد.
  • در سال ۲۰۱۷ نسخه ASP.NET Core 2.0 با بهبود عملکرد و اضافه شدن ویژگی‌های جدید منتشر شد.
  • در سال ۲۰۱۸ نسخه ASP.NET Core 2.1 با بهبودها و توسعه‌های دیگر منتشر شد.
  • در سال ۲۰۱۹ نسخه ASP.NET Core 3.0 با امکانات جدید منتشر شد.
  • در سال ۲۰۲۰ نسخه ASP.NET 5 با تغییر نام منتشر شد.
  • در سال ۲۰۲۱ نسخه ASP.NET 6 منتشر شد.
  • در سال ۲۰۲۲ نسخه ASP.NET 7 منتشر شد.
  • در سال ۲۰۲۳ نسخه ASP.NET 8 منتشر شد.

اگر امروز می‌خواهید پروژه جدیدی شروع کنید، قطعاً ASP.NET Core را انتخاب کنید. WebForms و ASP.NET MVC دیگر توصیه نمی‌شوند و فقط برای نگهداری پروژه‌های قدیمی استفاده می‌شوند.

آشنایی با HTTP و HTTPS

حالا وقت آن رسیده که با مهم‌ترین پروتکل دنیای وب آشنا شویم. هر کاری که در وب انجام می‌دهید، از خواندن یک خبر تا خرید از یک فروشگاه اینترنتی، همه از طریق پروتکل HTTP انجام می‌شود.

HTTP چیست؟

پروتکل HTTP مخفف Hyper Text Transfer Protocol می‌باشد. یکی از استانداردهای مهم در شبکه‌های اینترنتی است. این پروتکل برای ارتباط میان سرویس‌دهنده (server) و سرویس‌گیرنده (client) در وب استفاده می‌شود.

زمانی که در مرورگر خود آدرس یک وب‌سایت را وارد می‌کنید، توسط پروتکل HTTP است که می‌توانید اطلاعات آن سایت را درون مرورگر یا کامپیوتر خودتان مشاهده کنید. در واقع وقتی شما یک آدرس را درون مرورگر خود وارد می‌کنید، پروتکل HTTP یک درخواست یا Request از نوع GET به سمت سرور ارسال می‌کند. و در پاسخ یا Response اطلاعات مورد نیاز را دریافت و در مرورگر به کاربر یا همان کلاینت نمایش می‌دهد.

در کل می‌توان گفت پروتکل HTTP کلیه تعاملات بین کلاینت با سرور را انجام می‌دهد. هر کاری در وب توسط پروتکل HTTP صورت می‌پذیرد. به زبان ساده می‌توان گفت ارتباط بین سرور و کلاینت توسط پروتکل HTTP انجام می‌شود.

در واقع هرگونه انتقال داده روی وب توسط پروتکل HTTP انجام می‌شود. این پروتکل به صورت کلاینت-سرور عمل می‌کند، به این معنی که درخواست‌ها از سوی کلاینت (معمولاً یک مرورگر وب) آغاز می‌شوند. در پاسخ، سرور منابع مورد نیاز را ارسال می‌کند. این منابع می‌توانند شامل متن، تصاویر، ویدئوها، اسکریپت‌ها و موارد دیگر باشند.

پروتکل HTTP برای انتقال اطلاعات از سرور و نمایش آن‌ها در مرورگر وب استفاده می‌شود. این پروتکل در اوایل دهه ۱۹۹۰ میلادی ایجاد و به تدریج تکامل یافته است. از آن زمان تاکنون، HTTP به‌عنوان پایه‌ای برای تبادل داده‌ها در وب استفاده می‌شود. از اصلی‌ترین پروتکل‌های دسترسی به وب، پروتکل HTTP می‌باشد و هدف اصلی آن ایجاد ارتباط بین وب‌سرور و مرورگر است.

HTTPS چیست؟

HTTPS مخفف Hypertext Transfer Protocol Secure می‌باشد. یک پروتکل امنیتی برای انتقال داده‌ها در بستر وب است. این پروتکل نسخه ایمن‌تری از HTTP است که از رمزگذاری برای حفاظت از اطلاعات ارسالی بین کاربر و سرور استفاده می‌کند.

با استفاده از HTTPS، اطلاعات رمزگذاری شده و بین کلاینت و سرور منتقل می‌شوند. نماد HTTPS با علامت قفل در نوار آدرس مرورگر قابل مشاهده است. این پروتکل برای افزایش امنیت کاربران در ارتباط با وب‌سایت‌ها بسیار مهم است.

Hypertext یا ابرمتن چیست؟

منظور از Hypertext یا ابرمتن، متن‌های بزرگ و طولانی است که به صورت HTML نوشته می‌شوند. البته برخلاف اینکه کدهای نوشته‌شده فقط به صورت متنی هستند، بعد از پردازش توسط مرورگر کاربر لزوماً به صورت متنی نخواهند بود. یک سند HTML می‌تواند دارای تصویر، ویدئو، جدول، لینک و... باشد.

Status Code و HTTP Method

همان‌طور که در قسمت قبلی گفتیم، Request و Response از اجزای اصلی پروتکل HTTP می‌باشند. زمانی که شما در یک وب‌سایت وارد می‌شوید، یا در سایتی کامنت می‌گذارید و یا مطلبی را در یک سایت جستجو می‌کنید، در حقیقت برای هر کدام از این کارها یک Request از طرف مرورگر شما به سرور ارسال می‌شود و در مقابل سرور هم یک Response مناسب برای شما ارسال می‌کند.

HTTP Method چیست؟

هر Request ای که از طرف مرورگر به سمت سرور ارسال شود، حتماً دارای یک HTTP Method می‌باشد. در حقیقت HTTP Methodها به سرور اعلام می‌کنند که ما قصد انجام چه کاری را داریم. مثلاً قصد ایجاد یک دیتای جدید را داریم، یا قصد حذف یک دیتا را داریم، و یا قصد ایجاد یک دیتای جدید را داریم.

توجه داشته باشید که از چهار متد اولی بیشتر استفاده می‌شود:

Status Code چیست؟

هر زمان یک Request به سمت سرور ارسال می‌شود، حتماً سرور برای ما یک Response ارسال می‌کند حتی اگر عملیات ما با موفقیت انجام نشود. در پروتکل HTTP برای اینکه ما متوجه بشویم که عملیات در چه وضعیتی است، مثلاً موفقیت‌آمیز بوده یا شکست خورده، سرور به همراه Response برای ما یک Status Code ارسال می‌کند.

در واقع Status Code یک عدد است که ما با استفاده از این عدد متوجه می‌شویم که عملیات ما موفقیت‌آمیز بوده یا خیر و یا دارای چه وضعیتی می‌باشد. این اعداد به ۵ دسته تقسیم‌بندی می‌شوند: اعداد سری ۱۰۰، اعداد سری ۲۰۰، اعداد سری ۳۰۰، اعداد سری ۴۰۰ و اعداد سری ۵۰۰ که هر کدام معنا و مفهوم خاص خود را دارند.

Status Codeهای سری ۱۰۰ تا ۱۹۹

این سری از اعداد اطلاعاتی در خصوص نقل و انتقال بسته‌ها، مثل ارسال و دریافت فایل کاربرد دارند. مثلاً وقتی که یک فایل را در سرور آپلود می‌کنیم، بعد از دریافت فایل توسط سرور برای ما عدد ۱۰۰ ارسال می‌شود. یعنی فایل توسط سرور دریافت شده.

  • 100 Continue: تأیید دریافت اطلاعات توسط سرور را به مرورگر اطلاع می‌دهد
  • 101 Switching Protocols: برای تعویض پروتکل‌ها کاربرد دارد
  • 102 Processing: زمانی که یک درخواست به سرور ارسال می‌کنیم و سرور برای انجام آن درخواست نیاز به زمان دارد، برای مرورگر کد ۱۰۲ را می‌فرستد تا مرورگر متوجه بشود که این فعالیت زمان‌بر است و ارتباط را قطع نکند

Status Codeهای سری ۲۰۰ تا ۲۹۹

این سری از اعداد زمانی ارسال می‌شوند که سرور کاری را با موفقیت انجام داده است.

  • 200 OK: درخواست با موفقیت انجام شد و پاسخ در بدنه است.
  • 201 Created: منبع جدید با موفقیت ایجاد شد (پس از POST یا PUT).
  • 204 No Content: درخواست موفق بود اما پاسخی برای بازگرداندن وجود ندارد.

Status Codeهای سری ۳۰۰ تا ۳۹۹

این سری از اعداد برای Redirection (تغییر مسیر) استفاده می‌شوند.

  • 301 Moved Permanently: منبع برای همیشه به آدرس جدید منتقل شده است.
  • 302 Found: منبع به‌طور موقت به آدرس جدید منتقل شده است.
  • 304 Not Modified: منبع تغییری نکرده و از کش مرورگر استفاده کن.

Status Codeهای سری ۴۰۰ تا ۴۹۹

این سری از اعداد مربوط به خطاهای کلاینت هستند.

  • 400 Bad Request: درخواست ناقص یا نامعتبر است.
  • 401 Unauthorized: نیاز به احراز هویت دارد.
  • 403 Forbidden: کاربر احراز هویت شده اما دسترسی ندارد.
  • 404 Not Found: منبع مورد نظر پیدا نشد.
  • 405 Method Not Allowed: متد HTTP برای این منبع مجاز نیست.

Status Codeهای سری ۵۰۰ تا ۵۹۹

این سری از اعداد مربوط به خطاهای سرور هستند.

  • 500 Internal Server Error: خطای داخلی سرور.
  • 502 Bad Gateway: سرور واسط پاسخ نامعتبری از سرور اصلی دریافت کرده.
  • 503 Service Unavailable: سرویس به‌طور موقت در دسترس نیست.

HTTP Headers

هر Request یا Response در پروتکل HTTP یک فیلد HTTP Header دارد که اطلاعات و متادیتای اضافی در مورد Request یا Response را برای ما منتقل می‌کند. HTTP Header یا هدرهای HTTP به مشتری و سرور اجازه می‌دهند تا اطلاعات اضافه شده به صورت Request یا Response در HTTP منتقل شوند.

انواع HTTP Headers

HTTP Headerها بر اساس محتوای خود تقسیم‌بندی می‌شوند. در این بخش به معرفی آن‌ها می‌پردازیم:

  • هدرهای عمومی — General headers: هم برای Request و هم Response مورد استفاده قرار می‌گیرند.
  • هدرهای درخواستی — Request headers: حاوی اطلاعات بیشتری در مورد منبع Requestهای مشتری‌ها هستند.
  • هدرهای پاسخ‌دهنده — Response headers: اطلاعات بیشتری در مورد Response دارند، مثل مکان یا سرور ارائه‌دهنده آن.
  • هدرهای اطلاعاتی — Entity headers: حاوی اطلاعاتی درباره متن منبع هستند، مثل طول محتوا یا MIME type.

هدرهای عمومی — General headers

این هدرها هم برای Request و هم Response مورد استفاده قرار می‌گیرند. اما هیچ ارتباطی با داده‌های منتقل‌شده در متن ندارند.

  • فیلد Status: یک عدد است که ما با استفاده از این عدد متوجه می‌شویم که عملیات ما موفقیت‌آمیز بوده یا خیر و یا دارای چه وضعیتی می‌باشد.
  • فیلد VersionHTTP: ورژن HTTP را مشخص می‌کند.

هدرهای درخواستی — Request headers

این هدرها حاوی اطلاعات بیشتری در مورد منبع Requestهای مشتری‌ها هستند:

  • فیلد Accept: انواع داده‌های قابل ارسال به سرور را مشخص می‌کند.
  • فیلد Accept-Encoding: الگوریتم کدگذاری را مشخص می‌کند.
  • فیلد Accept-Language: برای سایت‌های چندزبانه خیلی کاربردی می‌باشد و به سرور نوع زبان کلاینت را اطلاع می‌دهد.
  • فیلد Connection: کنترل می‌کند که آیا اتصال شبکه بعد از پایان ارتباط فعلی باز باشد یا خیر.
  • فیلد Cookie: حاوی کوکی‌های ذخیره‌شده‌ای است که قبلاً توسط سرور با هدر Set-Cookie ارسال شده است.
  • فیلد Host: نام دامنه و پورت TCP را که سرور به آن گوش می‌دهد را مشخص می‌کند.
  • فیلد Referer: آدرس صفحه وب قبلی را نمایش می‌دهد. یعنی مشخص می‌کند، از چه صفحه و یا لینکی به این صفحه آمده‌ایم.
  • فیلد User-Agent: نام مرورگر، ورژن مرورگر، نام سیستم‌عامل و... را مشخص می‌کند و به سرور ارسال می‌کند.

هدرهای پاسخ‌دهنده — Response headers

این هدرها اطلاعات بیشتری در مورد Response دارند، مثل مکان یا سرور ارائه‌دهنده آن:

  • Cache-Control: تنظیمات مربوط به کش کردن پاسخ
  • Connection: وضعیت اتصال
  • Content-Encoding: الگوریتم فشرده‌سازی بدنه
  • Content-Length: اندازه بدنه پاسخ به بایت
  • Content-Type: نوع داده بدنه پاسخ
  • Date: تاریخ و ساعت ارسال پاسخ
  • Set-Cookie: ارسال کوکی از سرور به کلاینت
  • Location: آدرس جدید در ریدایرکت‌ها
  • Server: اطلاعات سرور
  • ETag: شناسه نسخه فعلی منبع (برای کش)

مثال واقعی از هدرها

HTTP Request 
GET /api/products HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Accept: application/json
Accept-Language: fa-IR,fa;q=0.9
Accept-Encoding: gzip, deflate
Connection: keep-alive
Cookie: sessionId=abc123
Referer: https://example.com/products
مهم

هدرها در HTTP/1.X به بزرگی و کوچکی حروف حساس نیستند (یعنی Content-Type با content-type یکی است)، اما در HTTP/2 به‌صورت اجباری با حروف کوچک نوشته می‌شوند.
