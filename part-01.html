01

آشنایی با .NET و .NET Standard

.NET یک فریم‌ورک نرم‌افزاری است که توسط شرکت مایکروسافت توسعه داده شده است. این فریم‌ورک امکان توسعه و اجرای برنامه‌های نرم‌افزاری را در محیط‌های مختلف از جمله وب، دسکتاپ، موبایل و سرور فراهم می‌کند[reference:0].

.NET یک پلتفرم توسعه نرم‌افزاری و اپن‌سورس است که شامل چندین فریم‌ورک مختلف نظیر .NET Framework، .NET Core و .NET 7 می‌شود و امکان اجرا بر روی سیستم‌عامل‌های مختلف از جمله Windows، Linux و macOS را دارد[reference:1].

کلمه .NET به یک فریم‌ورک کلان نرم‌افزاری اشاره می‌کند که امکان توسعه برنامه‌های متنوع را در محیط‌های مختلف فراهم می‌کند[reference:2]. .NET از زبان‌های برنامه‌نویسی متنوعی مانند C#، VB.NET و F# پشتیبانی می‌کند[reference:3].

نکته مهم

.NET خودش یک زبان برنامه‌نویسی نیست، بلکه یک پلتفرم یا اکوسیستم است. زبان‌های برنامه‌نویسی مختلفی روی این پلتفرم اجرا می‌شوند که معروف‌ترین آن‌ها C# است.

.NET Standard چیست؟

.NET Standard یک استاندارد تعریف‌شده توسط مایکروسافت است که به توسعه‌دهندگان امکان ایجاد کدهای قابل استفاده در انواع فریم‌ورک‌های .NET را می‌دهد[reference:4].

هدف اصلی این استاندارد، ایجاد یک بخش مشترک برای توسعه برنامه‌ها روی انواع فریم‌ورک‌های مختلف .NET است. به عبارت دیگر، اگر شما یک کتابخانه یا برنامه با استفاده از .NET Standard توسعه دهید، آن کد می‌تواند در هر فریم‌ورکی که از .NET Standard پشتیبانی می‌کند، اجرا شود[reference:5].

فریم‌ورک‌هایی مثل Xamarin، .NET Core و .NET Framework از .NET Standard پشتیبانی می‌کنند[reference:6].

تفاوت کلیدی

.NET Standard یک پیاده‌سازی از .NET نیست؛ بلکه مجموعه‌ای از APIها است که کلیه پیاده‌سازی‌های .NET باید آن‌ها را ارائه دهند. در واقع وقتی ما از .NET Standard استفاده می‌کنیم، مشکل اشتراک کد در همه سیستم‌عامل‌ها و پیاده‌سازی‌ها برای .NET برطرف می‌شود[reference:7].

مزایای استفاده از .NET Standard

  • قابلیت اجرا در چندین فریم‌ورک: کدهای توسعه‌داده‌شده با .NET Standard قابل استفاده در هر فریم‌ورکی است که از آن پشتیبانی کند[reference:8].
  • قابلیت به‌روزرسانی سریع: به‌روزرسانی‌های کتابخانه‌ها و برنامه‌ها سریع‌تر و ساده‌تر انجام می‌شود[reference:9].
  • کاهش پیچیدگی‌ها: به‌عنوان یک استاندارد مشترک، پیچیدگی میان فریم‌ورک‌ها را کاهش می‌دهد[reference:10].
  • پشتیبانی از محیط‌های مختلف: امکان توسعه برنامه‌ها را برای ویندوز، لینوکس و مک فراهم می‌کند[reference:11].

تفاوت .NET با .NET Standard

.NET به مجموعه‌ای از فریم‌ورک‌های مختلف مثل .NET Framework و .NET Core اشاره دارد که جدیدترین تکنولوژی‌های .NET را در بر می‌گیرد و بر روی یکپارچگی بیشتر بین پلتفرم‌ها تأکید دارد[reference:12].

.NET Standard استانداردی است که تعیین‌کننده قابلیت‌های مشترک بین انواع مختلف فریم‌ورک‌های .NET است[reference:13].

02

مقایسه .NET Framework و .NET Core

.NET Framework چیست؟

.NET Framework یک فریم‌ورک توسعه نرم‌افزار برای ساخت و اجرای برنامه‌های کاربردی در محیط ویندوز است. این فریم‌ورک توسط شرکت مایکروسافت ایجاد شده و ابتدا در سال ۲۰۰۲ عرضه شد[reference:14].

.NET Framework ابزارها و زیرساخت‌های لازم برای توسعه و اجرای برنامه‌های ویندوزی، وب و سرویس‌های ویندوزی را فراهم می‌کند. این فریم‌ورک به‌طور اصلی بر روی سیستم‌عامل ویندوز اجرا می‌شود و وابستگی به این سیستم‌عامل دارد[reference:15].

.NET Framework بخشی از دات‌نت است، مجموعه‌ای از فناوری‌ها برای ساخت اپلیکیشن برای لینوکس، macOS، ویندوز، iOS، اندروید و غیره[reference:16].

.NET Core چیست؟

.NET Core یکی از محصولات شرکت مایکروسافت است که در سال ۲۰۱۶ به بازار عرضه شد. این فریم‌ورک یک ابزار برنامه‌نویسی چندپلتفرمی و منبع‌باز است که روی تمامی پلتفرم‌های رایج در دنیا قابل‌استفاده است[reference:17].

.NET Core یک فریم‌ورک سازگار با تمامی سیستم‌عامل‌ها است و قابلیت ساخت برنامه‌های مختلف مناسب اندروید، iOS، ویندوز، لینوکس، وب، فضای ابری، IoT و هوش مصنوعی را دارد. از جمله ویژگی‌های خوب این پلتفرم سرعت و سبکی آن است و فقط برای اجرای قسمت اصلی کد به .NET Core نیاز دارید[reference:18].

تاریخچه

در اواخر سال ۲۰۲۰، .NET Core به .NET 5 تغییر نام داد و در ادامه، تا ویرایش .NET 8 معرفی شد[reference:19].

چرا .NET Core معرفی شد؟

نسخه قبلی این پلتفرم یعنی .NET Framework، یک ابزار با محدودیت‌های جدی بود. مهم‌ترین ضعف .NET Framework این بود که تنها در سیستم‌عامل ویندوز قابلیت اجرا داشت و روی سایر سیستم‌عامل‌ها قابل‌استفاده نبود[reference:20].

بنابراین، اغلب توسعه‌دهندگان به‌علت انحصاری بودن محصولات شرکت مایکروسافت، به‌مرور نسبت به نرم‌افزارهای این شرکت دلسرد شدند[reference:21]. علاوه بر این امروزه، استفاده از برنامه‌هایی که در تمامی دستگاه‌ها قابل‌اجرا باشند، رایج شده است. یک برنامه قوی باید بتواند تحت وب، روی دسکتاپ و روی تلفن‌های همراه و تبلت‌ها اجرا شود. به همین علت، نیاز به یک چارچوب واحد دارد. در واقع این موضوع، انگیزه اصلی شرکت مایکروسافت برای معرفی ابزار .NET Core بود[reference:22].

03

ASP.NET Core چیست؟

ASP.NET Core یک فریم‌ورک برای توسعه اپلیکیشن‌های مدرن وب و تحت فضای ابری است. این پلتفرم محبوب توسط کمپانی مایکروسافت توسعه داده شده و به‌صورت متن‌باز در گیت‌هاب در دسترس است[reference:23].

این امر ASP.NET Core را به یک پلتفرم جهانی با قابلیت‌های بسیار و نقص کمتر تبدیل کرده که خود می‌تواند یک عامل مهم در انتخاب آن به‌عنوان یک پلتفرم برای یادگیری توسعه‌دهندگان باشد[reference:24].

با آن می‌توان برای محیط‌های بک‌اند وب، اینترنت اشیا و اپلیکیشن‌های موبایلی برنامه‌نویسی کرد. این فریم‌ورک طوری طراحی شده است که به اجزای برنامه‌نویسی مانند APIها، کامپایلرها و زبان‌ها اجازه می‌دهد تا به سرعت تکامل پیدا کنند[reference:25].

ASP.NET Core یک پلتفرم پایه، قدرتمند و در عین حال پشتیبانی‌شده برای توسعه و اجرای برنامه‌ها و اپلیکیشن‌ها ارائه می‌دهد. از جمله مزایای اساسی این فریم‌ورک امکان نصب و راه‌اندازی نسخه‌های مختلف ASP.NET روی یک سرور است. شما می‌توانید با استفاده از آن پروژه‌های دلخواه‌تان را روی یک سرور و با استفاده از نسخه‌های مختلف پیاده‌سازی کنید[reference:26].

تاریخچه ASP.NET Core

ASP.NET Core اولین بار در سال ۲۰۱۶ منتشر شد و یک طراحی مجدد از نسخه‌های قبلی ASP.NET بود که فقط روی Windows قابل اجرا بود[reference:27].

ASP.NET Core نسخه اپن‌سورس ASP.NET است که روی MacOS، Linux و Windows اجرا می‌شود[reference:28].

مزایای استفاده از ASP.NET Core

کاربردهای بسیار زیاد این پلتفرم، باعث محبوبیت آن را در میان توسعه‌دهندگان افزایش داده است. عملاً این زبان یکی از بهترین زبان‌های توسعه نرم‌افزار کراس‌پلتفرم است که مزایای خاص خود را دارا بوده که در این مقاله به بررسی آن‌ها می‌پردازیم[reference:29].

  • کراس‌پلتفرم: شما با ASP.NET Core می‌توانید تنها با نوشتن یک کد، برنامه موردنظر خود را روی سیستم‌عامل‌های ویندوز، مک و لینوکس اجرا کنید[reference:30].
  • عملکرد بالا: یکی از مهم‌ترین ویژگی‌های هر نرم‌افزار سرعت بالا و کیفیت بالای آن است. ASP.NET Core هر آنچه که لازم دارید تا یک نرم‌افزار بهینه توسعه دهید را در اختیار شما قرار می‌دهد. این پلتفرم محبوب با بهره‌بردن از تکنولوژی IIS و وب‌سرورهای سبک و سریع، توسعه نرم‌افزار را سریع، بهینه و باکیفیت می‌کند[reference:31].
  • پشتیبانی از چهارچوب‌های ناهمزمان: ارسال چند درخواست به‌صورت همزمان به سرورها ممکن است سرور را دچار اختلال کند. این موضوع با استفاده از Asynchronous via async/await به‌طور کامل مدیریت می‌شود[reference:32].
  • پشتیبانی از MVC و وب API: یکی از ضروری‌ترین امور در پروژه‌ها استفاده از وب‌سرویس‌ها در آن‌ها است؛ چراکه در صورت درست عمل‌نکردن Web API پروژه دچار مشکل می‌شود. اما زمانی که از ASP.NET Core استفاده می‌کنید، درخواست‌ها از HTML به سمت JSON می‌روند سپس در اختیار کاربر قرار می‌گیرند[reference:33].
مهم

ASP.NET Core یک زبان برنامه‌نویسی نیست؛ بلکه یک فریم‌ورک است. ما با زبان C# کد می‌نویسیم و از ASP.NET Core برای ساخت وب‌سایت‌ها و APIها استفاده می‌کنیم.

04

الگوی طراحی MVC

MVC یک الگوی طراحی نرم‌افزار یا software design pattern است که مخفف کلمات Model، View و Controller است. این سه بخش نرم‌افزاری همیشه با هم در ارتباط هستند[reference:34].

Model وظیفه ارتباط با پایگاه داده را برعهده دارد. نقش View، نمایش اطلاعات برای کاربر است و Controller رابط بین Model و View است. یعنی اطلاعات را از Model می‌گیرد و جهت نمایش به View ارسال می‌کند[reference:35].

کاربر درخواست را به Controller می‌فرستد و از او پاسخ می‌گیرد — View و Model هر دو تحت کنترل Controller هستند

نحوه کار MVC

ابتدا کاربر درخواستی را توسط مرورگر خود ارسال می‌کند. این درخواست توسط Controller دریافت می‌شود و مورد پردازش قرار می‌گیرد. اگر درخواست به داده نیاز داشته باشد، Controller آن را از Model دریافت می‌کند. و یک View را انتخاب می‌کند و در صورت نیاز مدل/داده که دریافت کرده را به آن ارسال می‌کند. و در آخر View به کاربر در پاسخ درخواست او اطلاعات را نمایش می‌دهد[reference:36].

مزایای MVC

  • سرعت توسعه: MVC باعث می‌شود هر کد در جای مربوط به خودش باشد و نظمی که ایجاد می‌شود باعث افزایش سرعت توسعه کدها می‌شود[reference:37].
  • افزایش خوانایی کد: در MVC به علت مرتب سازی و تمیز بودن کدها، خوانایی کدها بالاتر می‌رود[reference:38].
  • آسان‌تر شدن دیباگ کد: در معماری MVC اگر مشکلی در کد ایجاد شود، به دلیل ساختار مناسب و منظم، مشکل کد سریع‌تر رفع می‌شود[reference:39].
  • تقسیم کاری بین توسعه‌دهندگان: در MVC می‌توان به هر توسعه‌دهنده دسترسی لازم به آن بخش را داد. مثلاً فرانت‌کارها به View دسترسی دارند یا بک‌اند کارها به Controllerها[reference:40].

معایب MVC

  • پیچیدگی MVC زیاد است: اگر برنامه‌نویس حرفه‌ای نباشد ممکن است با ساختار MVC زیاد آشنا نباشد و کار او سخت شود[reference:41].
  • مناسب نرم‌افزار کوچک نیست: اگر نرم‌افزار شما کوچک باشد و نیازی به توسعه نداشته باشد، MVC باعث افزایش پیچیدگی و کاهش سرعت برنامه خواهد شد[reference:42].
نتیجه‌گیری

در مجموع ممکن است الگوی MVC در ابتدا کمی پیچیده و مشکل به نظر برسد و ترجیح دهید بدون استفاده از این الگو پروژه‌های خود را پیش ببرید، اما اگر قصد انجام پروژه‌های بزرگ که نیازمند کار تیمی هستند را دارید هرگز از این الگو غافل نشوید. زیرا همان‌طور که در بالا توضیح داده شد این الگو با جداسازی View، Model و Controller امکان کار جداگانه بر روی هر یک از بخش‌ها را فراهم می‌کند[reference:43].

05

مقایسه WebForm، MVC و Core

ASP.NET WebForms

ASP.NET WebForms یک فریم‌ورک توسعه وب است که توسط مایکروسافت ارائه شده. این فریم‌ورک به توسعه وب‌سایت‌ها و برنامه‌های وب مبتنی بر سرور در محیط .NET کمک می‌کند. ASP.NET WebForms مبتنی بر مدل ویندوزی (Windows-based) و مدل رویدادی (event-driven) است[reference:44].

تاریخچه WebForms:

  • در سال ۲۰۰۲ اولین نسخه از ASP.NET Web Forms با .NET Framework 1.0 منتشر شد.
  • در سال ۲۰۰۵ نسخه ASP.NET 2.0 منتشر شد.
  • در سال ۲۰۰۸ نسخه ASP.NET 3.5 با افزونه‌ها و بهبودهای دیگر منتشر شد.
  • در سال ۲۰۱۰ نسخه ASP.NET 4.0 با ویژگی‌های جدیدتری منتشر شد.
  • در سال ۲۰۱۲ نسخه ASP.NET 4.5 با اضافه شدن ASP.NET Web API و SignalR منتشر شد[reference:45].

مزایا WebForms:

  • سرعت توسعه بالا با استفاده از کنترل‌های کاربری (Server Controls) و مدل برنامه‌نویسی Code-Behind.
  • ویژگی‌های بصری مانند ViewState برای مدیریت وضعیت صفحه.
  • سازگاری با پلتفرم‌ها و وب‌سرورهای مختلف[reference:46].

معایب WebForms:

  • کد HTML پیچیده و سنگین بودن صفحات.
  • سختی مدیریت وضعیت و Unit Testing.
  • عدم انعطاف‌پذیری وابستگی به وضعیت[reference:47].

ASP.NET MVC

ASP.NET MVC یک فریم‌ورک توسعه وب است. این فریم‌ورک بر مدل طراحی MVC تکیه دارد که به توسعه وب بر اساس تفکیک وظایف مربوط به مدل (Model)، نمایش (View) و کنترل (Controller) کمک می‌کند[reference:48].

تاریخچه ASP.NET MVC:

  • در سال ۲۰۰۹ اولین نسخه از ASP.NET MVC با .NET Framework 3.5 منتشر شد.
  • در سال ۲۰۱۰ نسخه ASP.NET MVC 2 منتشر شد.
  • در سال ۲۰۱۱ نسخه ASP.NET MVC 3 با اضافه شدن Razor و برخی ویژگی‌های جدید منتشر شد.
  • در سال ۲۰۱۲ نسخه ASP.NET MVC 4 با افزودن ASP.NET Web API منتشر شد.
  • در سال ۲۰۱۵ نسخه ASP.NET MVC 5 با بهبودها و اضافه شدن امکانات جدید منتشر شد[reference:49].

مزایا ASP.NET MVC:

  • تمرکز بر روی اصول RESTful و ساختار کلاینت-سرور.
  • قابلیت Unit Testing و امکانات تست‌پذیری بهتر[reference:50].

معایب ASP.NET MVC:

  • مدیریت فایل‌های JavaScript و CSS مقداری پیچیده است.
  • آشنایی برخی توسعه‌دهندگان با مفاهیم MVC ممکن است زمان‌بر باشد.
  • نیاز به مدیریت بیشتری روی URL و Routing می‌باشد[reference:51].

06

آشنایی با HTTP و HTTPS

زمانی که در مرورگر خود آدرس یک وب‌سایت را وارد می‌کنید، توسط پروتکل HTTP است که می‌توانید اطلاعات آن سایت را درون مرورگر یا کامپیوتر خودتان مشاهده کنید. در واقع وقتی شما یک آدرس را درون مرورگر خود وارد می‌کنید، پروتکل HTTP یک درخواست یا Request از نوع GET به سمت سرور ارسال می‌کند. و در پاسخ یا Response اطلاعات مورد نیاز را دریافت و در مرورگر به کاربر یا همان کلاینت نمایش می‌دهد[reference:54].

در کل می‌توان گفت پروتکل HTTP کلیه تعاملات بین کلاینت با سرور را انجام می‌دهد. هر کاری در وب توسط پروتکل HTTP صورت می‌پذیرد. به زبان ساده می‌توان گفت ارتباط بین سرور و کلاینت توسط پروتکل HTTP انجام می‌شود[reference:55].

HTTP چیست؟

پروتکل HTTP مخفف Hyper Text Transfer Protocol می‌باشد. یکی از استانداردهای مهم در شبکه‌های اینترنتی است. این پروتکل برای ارتباط میان سرویس‌دهنده (server) و سرویس‌گیرنده (client) در وب استفاده می‌شود[reference:56].

در واقع هرگونه انتقال داده روی وب توسط پروتکل HTTP انجام می‌شود. این پروتکل به صورت کلاینت-سرور عمل می‌کند، به این معنی که درخواست‌ها از سوی کلاینت (معمولاً یک مرورگر وب) آغاز می‌شوند. در پاسخ، سرور منابع مورد نیاز را ارسال می‌کند. این منابع می‌توانند شامل متن، تصاویر، ویدئوها، اسکریپت‌ها و موارد دیگر باشند[reference:57].

پروتکل HTTP برای انتقال اطلاعات از سرور و نمایش آن‌ها در مرورگر وب استفاده می‌شود. این پروتکل در اوایل دهه ۱۹۹۰ میلادی ایجاد و به تدریج تکامل یافته است. از آن زمان تاکنون، HTTP به عنوان پایه‌ای برای تبادل داده‌ها در وب استفاده می‌شود. از اصلی‌ترین پروتکل‌های دسترسی به وب، پروتکل HTTP می‌باشد و هدف اصلی آن ایجاد ارتباط بین وب‌سرور و مرورگر است[reference:58].

HTTPS چیست؟

HTTPS مخفف Hypertext Transfer Protocol Secure می‌باشد. یک پروتکل امنیتی برای انتقال داده‌ها در بستر وب است. این پروتکل نسخه ایمن‌تری از HTTP است که از رمزگذاری برای حفاظت از اطلاعات ارسالی بین کاربر و سرور استفاده می‌کند[reference:59].

با استفاده از HTTPS، اطلاعات رمزگذاری شده و بین کلاینت و سرور منتقل می‌شوند. نماد HTTPS با علامت قفل در نوار آدرس مرورگر قابل مشاهده است. این پروتکل برای افزایش امنیت کاربران در ارتباط با وب‌سایت‌ها بسیار مهم است[reference:60].

Hypertext یا ابرمتن چیست؟

منظور از Hypertext یا ابرمتن، متن‌های بزرگ و طولانی است که به صورت HTML نوشته می‌شوند. البته برخلاف اینکه کدهای نوشته‌شده فقط به صورت متنی هستند، بعد از پردازش توسط مرورگر کاربر لزوماً به صورت متنی نخواهند بود. یک سند HTML می‌تواند دارای تصویر، ویدئو، جدول، لینک و... باشد[reference:61].

07

Status Code و HTTP Method

همان‌طور که در قسمت قبلی گفتیم، Request و Response از اجزای اصلی پروتکل HTTP می‌باشند. زمانی که شما در یک وب‌سایت وارد می‌شوید، یا در سایتی کامنت می‌گذارید و یا مطلبی را در یک سایت جستجو می‌کنید، در حقیقت برای هر کدام از این کارها یک Request از طرف مرورگر شما به سرور ارسال می‌شود و در مقابل سرور هم یک Response مناسب برای شما ارسال می‌کند[reference:62].

HTTP Method چیست؟

هر Request ای که از طرف مرورگر به سمت سرور ارسال شود، حتماً دارای یک HTTP Method می‌باشد. در حقیقت HTTP Methodها به سرور اعلام می‌کنند که ما قصد انجام چه کاری را داریم. مثلاً قصد ایجاد یک دیتای جدید را داریم، یا قصد حذف یک دیتا را داریم، و یا قصد ایجاد یک دیتای جدید را داریم[reference:63].

توجه داشته باشید که از چهار متد اولی بیشتر استفاده می‌شود[reference:64]:

متدتوضیحکاربرد

Status Code چیست؟

هر زمان یک Request به سمت سرور ارسال می‌شود، حتماً سرور برای ما یک Response ارسال می‌کند حتی اگر عملیات ما با موفقیت انجام نشود. در پروتکل HTTP برای اینکه ما متوجه بشویم که عملیات در چه وضعیتی است، مثلاً موفقیت‌آمیز بوده یا شکست خورده، سرور به همراه Response برای ما یک Status Code ارسال می‌کند[reference:72].

در واقع Status Code یک عدد است که ما با استفاده از این عدد متوجه می‌شویم که عملیات ما موفقیت‌آمیز بوده یا خیر و یا دارای چه وضعیتی می‌باشد. این اعداد به ۵ دسته تقسیم‌بندی می‌شوند: اعداد سری ۱۰۰، اعداد سری ۲۰۰، اعداد سری ۳۰۰، اعداد سری ۴۰۰ و اعداد سری ۵۰۰ که هر کدام معنا و مفهوم خاص خود را دارند[reference:73].

Status Codeهای سری ۱۰۰ تا ۱۹۹

این سری از اعداد اطلاعاتی در خصوص نقل و انتقال بسته‌ها، مثل ارسال و دریافت فایل کاربرد دارند. مثلاً وقتی که یک فایل را در سرور آپلود می‌کنیم، بعد از دریافت فایل توسط سرور برای ما عدد ۱۰۰ ارسال می‌شود. یعنی فایل توسط سرور دریافت شده[reference:74].

  • 100 Continue: تأیید دریافت اطلاعات توسط سرور را به مرورگر اطلاع می‌دهد[reference:75]
  • 101 Switching Protocols: برای تعویض پروتکل‌ها کاربرد دارد[reference:76]
  • 102 Processing: زمانی که یک درخواست به سرور ارسال می‌کنیم و سرور برای انجام آن درخواست نیاز به زمان دارد، برای مرورگر کد ۱۰۲ را می‌فرستد تا مرورگر متوجه بشود که این فعالیت زمان‌بر است و ارتباط را قطع نکند[reference:77]

Status Codeهای سری ۲۰۰ تا ۲۹۹

این سری از اعداد زمانی ارسال می‌شوند که سرور کاری را با موفقیت انجام داده است[reference:78].

  • 200 OK: درخواست با موفقیت انجام شد و پاسخ در بدنه است.
  • 201 Created: منبع جدید با موفقیت ایجاد شد (پس از POST یا PUT).
  • 204 No Content: درخواست موفق بود اما پاسخی برای بازگرداندن وجود ندارد.

Status Codeهای سری ۳۰۰ تا ۳۹۹

این سری از اعداد برای Redirection (تغییر مسیر) استفاده می‌شوند.

  • 301 Moved Permanently: منبع برای همیشه به آدرس جدید منتقل شده است.
  • 302 Found: منبع به‌طور موقت به آدرس جدید منتقل شده است.
  • 304 Not Modified: منبع تغییری نکرده و از کش مرورگر استفاده کن.

Status Codeهای سری ۴۰۰ تا ۴۹۹

این سری از اعداد مربوط به خطاهای کلاینت هستند.

  • 400 Bad Request: درخواست ناقص یا نامعتبر است.
  • 401 Unauthorized: نیاز به احراز هویت دارد.
  • 403 Forbidden: کاربر احراز هویت شده اما دسترسی ندارد.
  • 404 Not Found: منبع مورد نظر پیدا نشد.
  • 405 Method Not Allowed: متد HTTP برای این منبع مجاز نیست.

Status Codeهای سری ۵۰۰ تا ۵۹۹

این سری از اعداد مربوط به خطاهای سرور هستند.

  • 500 Internal Server Error: خطای داخلی سرور.
  • 502 Bad Gateway: سرور واسط پاسخ نامعتبری از سرور اصلی دریافت کرده.
  • 503 Service Unavailable: سرویس به‌طور موقت در دسترس نیست.

08

HTTP Headers

هر Request یا Response در پروتکل HTTP یک فیلد HTTP Header دارد که اطلاعات و متادیتای اضافی در مورد Request یا Response را برای ما منتقل می‌کند. HTTP Header یا هدرهای HTTP به مشتری و سرور اجازه می‌دهند تا اطلاعات اضافه شده به صورت Request یا Response در HTTP منتقل شوند[reference:79].

انواع HTTP Headers

HTTP Headerها بر اساس محتوای خود تقسیم‌بندی می‌شوند. در این بخش به معرفی آن‌ها می‌پردازیم[reference:80]:

  • هدرهای عمومی — General headers: هم برای Request و هم Response مورد استفاده قرار می‌گیرند[reference:81].
  • هدرهای درخواستی — Request headers: حاوی اطلاعات بیشتری در مورد منبع Requestهای مشتری‌ها هستند[reference:82].
  • هدرهای پاسخ‌دهنده — Response headers: اطلاعات بیشتری در مورد Response دارند، مثل مکان یا سرور ارائه‌دهنده آن[reference:83].
  • هدرهای اطلاعاتی — Entity headers: حاوی اطلاعاتی درباره متن منبع هستند، مثل طول محتوا یا MIME type[reference:84].

هدرهای عمومی — General headers

این هدرها هم برای Request و هم Response مورد استفاده قرار می‌گیرند. اما هیچ ارتباطی با داده‌های منتقل‌شده در متن ندارند[reference:85].

  • فیلد Status: یک عدد است که ما با استفاده از این عدد متوجه می‌شویم که عملیات ما موفقیت‌آمیز بوده یا خیر و یا دارای چه وضعیتی می‌باشد[reference:86].
  • فیلد VersionHTTP: ورژن HTTP را مشخص می‌کند[reference:87].

هدرهای درخواستی — Request headers

این هدرها حاوی اطلاعات بیشتری در مورد منبع Requestهای مشتری‌ها هستند[reference:88]:

  • فیلد Accept: انواع داده‌های قابل ارسال به سرور را مشخص می‌کند[reference:89].
  • فیلد Accept-Encoding: الگوریتم کدگذاری را مشخص می‌کند[reference:90].
  • فیلد Accept-Language: برای سایت‌های چندزبانه خیلی کاربردی می‌باشد و به سرور نوع زبان کلاینت را اطلاع می‌دهد[reference:91].
  • فیلد Connection: کنترل می‌کند که آیا اتصال شبکه بعد از پایان ارتباط فعلی باز باشد یا خیر[reference:92].
  • فیلد Cookie: حاوی کوکی‌های ذخیره‌شده ای است که قبلاً توسط سرور با هدر Set-Cookie ارسال شده است[reference:93].
  • فیلد Host: نام دامنه و پورت TCP را که سرور به آن گوش می‌دهد را مشخص می‌کند[reference:94].
  • فیلد Referer: آدرس صفحه وب قبلی را نمایش می‌دهد. یعنی مشخص می‌کند، از چه صفحه و یا لینکی به این صفحه آمده‌ایم[reference:95].
  • فیلد User-Agent: نام مرورگر، ورژن مرورگر، نام سیستم‌عامل و... را مشخص می‌کند و به سرور ارسال می‌کند[reference:96].

هدرهای پاسخ‌دهنده — Response headers

این هدرها اطلاعات بیشتری در مورد Response دارند، مثل مکان یا سرور ارائه‌دهنده آن[reference:97]:

  • Cache-Control: تنظیمات مربوط به کش کردن پاسخ
  • Connection: وضعیت اتصال
  • Content-Encoding: الگوریتم فشرده‌سازی بدنه
  • Content-Length: اندازه بدنه پاسخ به بایت
  • Content-Type: نوع داده بدنه پاسخ
  • Date: تاریخ و ساعت ارسال پاسخ
  • Set-Cookie: ارسال کوکی از سرور به کلاینت
  • Location: آدرس جدید در ریدایرکت‌ها
  • Server: اطلاعات سرور
  • ETag: شناسه نسخه فعلی منبع (برای کش)

مثال واقعی از هدرها

HTTP Request 
GET /api/products HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Accept: application/json
Accept-Language: fa-IR,fa;q=0.9
Accept-Encoding: gzip, deflate
Connection: keep-alive
Cookie: sessionId=abc123
Referer: https://example.com/products
مهم

هدرها در HTTP/1.X به بزرگی و کوچکی حروف حساس نیستند (یعنی Content-Type با content-type یکی است)، اما در HTTP/2 به‌صورت اجباری با حروف کوچک نوشته می‌شوند.
