01

.NET چیست؟

فرض کنید می‌خواهید خانه بسازید. به یک کارگاه با ابزارهای مختلف، مصالح ساختمانی و کارگر نیاز دارید. در دنیای برنامه‌نویسی هم .NET نقش همان کارگاه را دارد: همه ابزارهای لازم برای ساخت برنامه را در اختیار شما می‌گذارد.

.NET یک پلتفرم است، نه یک زبان برنامه‌نویسی. روی آن می‌توانید با زبان‌های مختلف مثل C#، VB.NET یا F# برنامه بنویسید.

اجزای اصلی .NET

.NET از سه لایه اصلی ساخته شده که با هم کار می‌کنند:

زبان‌ها روی کتابخانه و CLR سوار هستند؛ همه با هم یک پلتفرم واحد می‌سازند

تاریخچه کوتاه .NET

  • ۲۰۰۲ — .NET Framework: اولین نسخه، فقط برای ویندوز.
  • ۲۰۱۶ — .NET Core: بازنویسی کامل، چندسکویی و متن‌باز.
  • ۲۰۲۰ به بعد — .NET 5 و بالاتر: کلمه Core حذف شد و همه‌چیز زیر نام .NET با نسخه‌بندی سالانه یکپارچه شد.
جمع‌بندی

.NET = یک پلتفرم کامل. زبان C# فقط یکی از زبان‌هایی است که روی آن کار می‌کند.

02

.NET Framework در برابر .NET Core

این دو را مثل دو برادر در نظر بگیرید: بزرگ‌تر در سال ۲۰۰۲ به دنیا آمد و فقط در یک شهر (ویندوز) می‌تواند زندگی کند. کوچک‌تر در سال ۲۰۱۶ به دنیا آمد و هر جای دنیا (ویندوز، لینوکس، مک) می‌تواند برود.

.NET Framework — قدیمی و محدود

فقط روی ویندوز اجرا می‌شود، متن‌باز نیست و مایکروسافت دیگر نسخه جدیدی برایش منتشر نمی‌کند. آخرین نسخه ۴.۸.۱ است.

.NET Core — مدرن و آزاد

روی ویندوز، لینوکس و مک اجرا می‌شود، کاملاً متن‌باز است، سریع‌تر است و برای محیط‌های ابری و Docker طراحی شده است.

چرا .NET Core ساخته شد؟

سه دلیل اصلی مایکروسافت را به ساخت نسخه جدید وادار کرد:

  • دنیای چندسکویی: بیشتر سرورهای امروزی لینوکسی هستند.
  • نیاز به سرعت: برنامه‌های وب باید سریع پاسخ دهند.
  • محیط‌های ابری: ابزارهایی مثل Docker و Kubernetes محبوب شده بودند.

03

ASP.NET Core چیست؟

.NET Core را مثل یک شهر بزرگ در نظر بگیرید که همه امکانات را دارد. ASP.NET Core در این شهر، ابزار ساخت مغازه است — یعنی مجموعه‌ای از ابزارهای آماده برای ساختن وب‌سایت، وب‌سرویس و API.

به زبان ساده، ASP.NET Core یک فریم‌ورک وب است که در سال ۲۰۱۶ منتشر شد و جایگزین نسخه‌های قدیمی ASP.NET شد.

جایگاه ASP.NET Core در .NET

هر چه به داخل می‌رویم، تخصصی‌تر می‌شود: از پلتفرم کلی تا الگوی MVC

مزایای کلیدی

  • چندسکویی: روی هر سیستم‌عاملی اجرا می‌شود.
  • سریع: یکی از سریع‌ترین فریم‌ورک‌های وب در جهان.
  • متن‌باز: کد روی GitHub برای همه قابل مشاهده است.
  • تزریق وابستگی داخلی: بدون کتابخانه اضافی.
  • خط لوله انعطاف‌پذیر: کنترل کامل روی پردازش درخواست‌ها.

با ASP.NET Core چه چیزهایی می‌سازند؟

  • وب‌سایت‌های MVC — سایت‌های پویا با صفحات سمت سرور
  • APIهای RESTful — برای اپلیکیشن‌های موبایل و SPA
  • Blazor — وب اپلیکیشن با C# به‌جای JavaScript
  • SignalR — اپلیکیشن‌های Real-time مثل چت
  • gRPC — سرویس‌های میکرو با عملکرد بالا
04

الگوی طراحی MVC

MVC را با یک رستوران مقایسه کنید. سه بخش اصلی دارد:

  • آشپزخانه (Model): غذا (داده) و دستور پخت (منطق) اینجاست.
  • میز غذا (View): چیزی که مشتری (کاربر) می‌بیند.
  • گارسون (Controller): واسطه بین آشپزخانه و میز.

مشتری سفارش می‌دهد → گارسون آن را به آشپزخانه می‌برد → غذا آماده می‌شود → گارسون غذا را روی میز می‌گذارد.

Controller مرکز ارتباط است؛ با Model و View کار می‌کند و پاسخ را به کاربر برمی‌گرداند

سه جزء اصلی

Model — مغز برنامه

هر چیزی که مربوط به داده و منطق باشد در Model است: ساختار اطلاعات (مثلاً «یک محصول چه ویژگی‌هایی دارد»)، دسترسی به دیتابیس، اعتبارسنجی و قوانین کسب‌وکار.

View — ظاهر برنامه

همان چیزی که کاربر در مرورگر می‌بیند. در ASP.NET Core MVC، Viewها با فناوری Razor (فایل‌های .cshtml) نوشته می‌شوند و C# با HTML ترکیب می‌شود.

Controller — مدیر برنامه

هر درخواست کاربر اول به Controller می‌رسد. Controller تصمیم می‌گیرد کدام Model و کدام View استفاده شوند، داده را از Model می‌گیرد و به View می‌فرستد.

یک درخواست در MVC چطور پردازش می‌شود؟

  1. کاربر درخواست می‌فرستد مثلاً روی لینک «محصولات» کلیک می‌کند و آدرس /Products باز می‌شود.
  2. Controller درخواست را می‌گیرد سیستم آن را به ProductsController و متد Index() هدایت می‌کند.
  3. Controller از Model داده می‌خواهد متد Index() از Model می‌خواهد لیست محصولات را برگرداند.
  4. Model داده را آماده می‌کند Model از دیتابیس می‌خواند و لیست را برمی‌گرداند.
  5. Controller داده را به View می‌دهد لیست محصولات به View مخصوص ارسال می‌شود.
  6. View صفحه را می‌سازد View داده‌ها را در قالب HTML می‌ریزد و نتیجه به مرورگر می‌رود.

مزایای MVC

  • جداسازی وظایف: هر بخش کار خودش را می‌کند، بدون دخالت در بقیه.
  • تست‌پذیری: می‌توان Model و Controller را بدون مرورگر تست کرد.
  • نگهداری آسان: تغییر ظاهر فقط View را لمس می‌کند.
  • کار تیمی: چند نفر می‌توانند هم‌زمان روی بخش‌های مختلف کار کنند.
یک نکته

برای پروژه‌های خیلی کوچک، MVC ممکن است بیش از حد ساختارمند به نظر برسد. اما برای پروژه‌های متوسط و بزرگ، همین ساختار باعث می‌شود در بلندمدت نگهداری آسان‌تر شود.

05

تکامل ASP.NET: از WebForms تا Core

مایکروسافت سه نسل مختلف برای ساخت وب‌سایت ارائه کرده است. هر نسل درس‌های نسل قبل را به کار گرفت.

سه نسل ASP.NET، هر کدام با درس‌گرفتن از نسل قبل

نسل اول: WebForms

ایده اصلی این بود که برنامه‌نویسی وب شبیه برنامه‌نویسی ویندوز شود. برنامه‌نویس کامپوننت‌های آماده مثل دکمه و جعبه متن را می‌گذاشت و فریم‌ورک خودش HTML نهایی را تولید می‌کرد. مشکل: کنترل کم روی HTML و فایل‌های سنگین (به‌خاطر مفهومی به نام ViewState).

نسل دوم: ASP.NET MVC

با الهام از فریم‌ورک‌هایی مثل Ruby on Rails، مایکروسافت الگوی MVC را آورد. حالا برنامه‌نویس کنترل کامل روی HTML داشت و کد قابل تست بود. اما هنوز فقط روی ویندوز کار می‌کرد.

نسل سوم: ASP.NET Core

بازنویسی کامل از صفر: چندسکویی، متن‌باز، سریع‌تر و مناسب Docker و ابر. این نسخه امروز استاندارد است.

06

HTTP و HTTPS

وقتی در مرورگر آدرس google.com را وارد می‌کنید، در پشت صحنه این اتفاق می‌افتد: مرورگر یک درخواست می‌فرستد، سرور آن را پردازش می‌کند و یک پاسخ برمی‌گرداند.

مرورگر درخواست می‌فرستد، سرور پاسخ می‌دهد — همه طبق قوانین HTTP

HTTP چیست؟

HTTP مخفف Hypertext Transfer Protocol است؛ یعنی «قوانین جابه‌جایی صفحات وب». یک پروتکل است — مجموعه‌ای از قوانین توافق‌شده که مرورگر و سرور با آن با هم حرف می‌زنند.

ویژگی مهم: بدون حالت

HTTP بدون حالت (Stateless) است. یعنی هر درخواست مستقل است و سرور اطلاعات درخواست قبلی را نگه نمی‌دارد. برای اینکه سایت بداند شما وارد شده‌اید، از Cookie و Session استفاده می‌شود (در قسمت‌های بعدی توضیح داده می‌شود).

HTTPS چیست؟

HTTPS نسخه امن HTTP است. تمام اطلاعات بین مرورگر و سرور رمزنگاری می‌شود.

  • HTTP: مثل نامه باز — هر کسی در مسیر می‌تواند بخواند.
  • HTTPS: مثل نامه در پاکت دربسته — فقط گیرنده می‌تواند باز کند.

08

HTTP Headers

وقتی بسته پستی می‌فرستید، روی آن می‌نویسید: نام گیرنده، آدرس، وزن، محتویات. HTTP Header هم همین نقش را دارد — اطلاعات اضافی همراه درخواست یا پاسخ که به سرور و مرورگر کمک می‌کند بفهمند با چه چیزی سر و کار دارند.

ساختار یک درخواست

سه لایه: خط درخواست، هدرها، بدنه

در HTTP/1.X بزرگی و کوچکی حروف در هدرها مهم نیست (Content-Type و content-type یکی هستند). در HTTP/2 هدرها همیشه با حروف کوچک نوشته می‌شوند.
